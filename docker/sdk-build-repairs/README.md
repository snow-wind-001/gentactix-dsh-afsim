# SDK rc5 artifact provenance and rebuild guide

The delivered wheels use upstream https://github.com/deepseek-ai/deepseek-harness at `b830ec950faba0a46dda564be3e2d854afed94f1` (`dsh-v0.2.1-rc.5`), licensed MIT. The original wheel manifests and licenses identify the distributed artifacts. Both exact wheel byte hashes are in `../sdk-wheels.json`.

The local build repaired locked dependency deployment, enabled GZip SEA compression and clamped zero-sized SEA decompression bounds. These portable repair sources correspond to those changes. No developer-home path is required: run in a separate checkout pinned to the above commit, install that checkout's locked dependencies using its declared pnpm version, run `node /path/to/make-locked-deploy.mjs "$PWD"`, `python /path/to/apply-build-repairs.py` and `python /path/to/fix-empty-sea-entry.py`, then use upstream `scripts/build-exe-for-python-sdk.ts --help` and `scripts/build-python-release.py --help` for Linux x64 runtime and wheel packaging. Use `--package sdk|runtime --version 0.2.1rc5` for the upstream wheel builder; do not change SDK behavior.

Upstream's wheel verifier enforces the PyPI 100,000,000-byte file ceiling, so the runtime wheel is already produced but that final publication guard reports an error for this 144,887,797-byte artifact. The reviewed runtime wheel is distributed through GitHub Release assets instead of PyPI; the guard is not evidence of an invalid wheel. Preserve the generated artifact, verify metadata/license/hash and test the runtime before redistribution. Exact bit reproduction of a fresh source build has not been established. Production Docker builds consume the reviewed release wheels, verify exact SHA-256 and install them with a BuildKit bind mount so the wheel archives never occupy final image layers.
