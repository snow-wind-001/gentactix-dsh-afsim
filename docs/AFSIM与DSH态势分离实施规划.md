# AFSIM 与 DSH 态势分离实施规划

日期：2026-10-27。基线：3.3.0。用户要求：将 AFSIM 作为 DSH 领域插件接入现有项目，覆盖现有场景，并减少把完整战场状态放入模型上下文的做法。

## 架构与状态归属

- 复用现有 DSH/Cordis 工具注册、会话、事件、请求预算、取消和分支；不另建模型传输或智能体运行时。
- 已提交的 `war_state`、单位身份、人员装备账、补给、程序时钟及轨迹仍由应用保存。AFSIM 计算其实际支持的实体运动或交互，返回有运行证据的候选结果；原子校验通过后才提交。
- 模型仅接收任务摘要、受控单位及变化，通过有数量限制的工具读取细节，提交结构化命令；不再要求模型重写全部单位、人员装备和静态地图。
- AFSIM 仿真时间使用相对秒；历史历法与回合时间由现有 `sim_clock` 管理。
- 失败、取消、失配、缺少运行文件均拒绝本次提交；不能把内部测试替身或原规则计算标成 AFSIM 执行成功。

## 实施与验收

1. 核实本机 AFSIM 版本，隔离解包、依赖及运行目录，实际运行最小场景。AFSIM 私有程序、源码、资料及运行输出不加入公开仓库或适配器包；MIT 参考组件保留许可证与固定版本。
2. 建立领域适配器：稳定身份映射、单位制、场景编译、进程执行、结构化结果解析、取消与失败回滚。先用真实运行验证时间推进、待命与移动。
3. 接入现有 DSH 原生领域插件，提供限量观察和命令候选接口，保持人工命令优先及已有权限边界。模型的公开决策摘要与 AFSIM 执行事实分别留痕。
4. 全目录检查：逐场检查地理范围、初态和兵种映射，进行真实装载、移动与状态往返。保留人员装备与库存的未知值及历史统计口径。
5. 按战役规则分层验证战损、补给、工事、坑道、破袭和目标判定。现有教学规则只能标为教学规则；未经验证的 AFSIM 模型不能默认覆盖这些规则。
6. 前端展示当前执行后端、可用能力、运行证据和错误；旧存档及默认工作方式保持兼容。
7. 比较相同初态和命令下的提示词字符数、实际 token、模型请求次数、仿真耗时和端到端耗时；保持已有引擎高思考强度与 64k 上限。

## 事实与能力边界

DSIAC 公开资料说明 AFSIM 支持 C++ 扩展、Python 绑定、Windows/Linux，但通过 MOU/ITA 等协议提供源码及程序。公开介绍页面不构成公开再分发许可；本项目只交付自行编写的适配代码。

覆盖必须分别报告“目录映射”“实体装载”“命令执行”“人员装备连续性”“资源约束”“战役规则”和“历史标定”。仅用通用实体跑通移动不能称为全部战役已完成物理或历史验收。

资料：[DSIAC AFSIM 介绍与分发说明](https://dsiac.dtic.mil/models/afsim/)、[DCS 产品说明](https://www.dcscorp.com/products/afsim/)。

## 运行记录

组件固定在 `vendor/afsim/`，用户本机本体、原始归档、Wine 与运行数据在被忽略的 `vendor/afsim/local/afsim/`。验收证据在 `.cache/qa/afsim-bridge/`；保留已有 Vault、模型设置、保存对局和本机安装程序。首次验证后续已迁移到上述稳定目录，旧缓存路径不再作为组件入口。

当前源码、独立适配器包及冻结后端已完成集成，验收明细见[接入验收](AFSIM接入验收-2026-10-27.md)。45/45 指目录装载与命令往返，不能解释为45个战役的历史编制、武器效能、道路/DEM或战损均已校准。阶段5目前复用20份局部教学规则，其余场景仅执行运动并保留账本。

## 前端接入简报

- 入口沿用现有LaunchScreen配置页，增加初始化时选择的执行后端，默认旧模式。AFSIM缺失时选项不可用；其执行使用开放推演，固定局部演习仍可选。
- CreateSessionRequest.execution_backend传递选择，快照settings.execution_backend恢复实际选择，缺字段的旧存档按旧模式解释。切换表单不改变正在打开的战局后端。
- AFSimPanel显示实体数、耗时、上下文策略与证据。仅原生MCP执行完成且退出码为0才显示真实成功；配置、初态校验、运行中、测试数据与失败分别表达。
- 人工完整命令无需模型时显示跳过说明，运动、教学规则与尚未实现的武器资源效果分别注明来源。
- 沿用现有布局和颜色。选择器具有关联label和稳定测试选择器；原生details支持键盘；窄屏统计项换行。
- 验证API合同及回滚、vue-tsc、生产构建和宽窄视口浏览器流程，覆盖默认旧模式、组件可用与缺失、旧存档、跳过模型及实际证据。

## 后续模型扩展

地形/道路、视线与射界、历史武器参数、通信退化和补给吞吐模型，仍需分别建立受版本管理的参数、来源与对照案例。在这些模块通过真实运行验收前，继续显示“未建模”或“教学规则”，不能只把公式换成 AFSIM 类型名就提高可信度标记。
