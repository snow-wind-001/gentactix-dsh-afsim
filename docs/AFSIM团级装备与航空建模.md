# AFSIM 团级以上装备与航空建模

## 结论与粒度

本项目接入的是 **AFSIM**。保留 Vue/Leaflet/Electron 前端，DSH 下达全局及单位命令，AFSIM 后台产生运动、事件和已登记模型的计算结果，应用校验后保存检查点。无需迁移到 AirSim，也无需为每名士兵、每发子弹建立实体。

团级以上采用“编组平台 + 分类装备账 + 任务实体”。平台的位置代表指挥/集结参考点，不代表全团集中在一个点；需要编组展开范围与集结程度，否则面积火力会失真。只有渡河、桥梁、航空出动等影响战役进程的行动下沉到任务级。AFSIM 的 mover、航路、延迟创建、脚本回调和原生 MCP 已可复用；业务仅编译封闭模板，不另造仿真时钟、Agent 运行时或地图引擎。

## 必要模型及数据缺口

| 模型 | 推荐粒度与必要数据 | 当前边界与下一步 |
| --- | --- | --- |
| 步兵/摩托化/机械化编组 | 人员可用、负伤/非战斗减员；展开面积、疲劳、训练、工事与交通条件 | 既有固定想定仅为每编组100人、4件通用装备的合成局部模型，不能称真实团级编制；需逐场补编制与展开面积 |
| 装甲、反坦克 | 按车型或性能类别分组；可用/待修/毁伤、弹药、防护方向、地形通行 | 不逐辆六自由度建模；先建立分类守恒账与目标类型效能矩阵，再标定，不把HP换算成坦克数量 |
| 炮兵、远程火力 | 火炮/发射器组、弹种库存、射程、射击周期、压制持续、观察校射、反炮兵风险 | 运动和现有教学射击已接入；真实间瞄火力、压制恢复与分类装备毁伤尚未完成 |
| 防空 | 高炮/机枪/导弹类别、可用数量、部署、探测与交战包线、弹药 | 本轮航空模型只有明确标注的合成防空损失系数；没有雷达、导弹或历史防空编制标定 |
| 航空 | 航空资源池 + 每批次任务；可用飞机、架次、航空油弹、入场点、航路、到达、目标复核、防空、战果、返场 | 本轮在两个已登记航空局部想定实现；飞机不属于请求支援的地面编组，航空油弹独立结算 |
| 工兵/桥梁/渡口 | 设施容量、搭建/修复时间、通过率、毁坏与修复资源 | 应成为河流场景的独立任务对象；当前未实现容量排队，不能宣称已真实模拟渡河拥堵 |
| 运输/仓库/维修/卫生 | 补给节点与路线、运力、库存、需求、配送时延、维修/伤员回归 | 现有教学补给有库存与连通约束；未做吨公里、道路吞吐、车辆维修与伤员后送标定 |
| 指挥/侦察 | 通信覆盖与延迟、已知/未知/过时情报、来源时间 | DSH已有有界观察与轨迹；现有态势仍是应用全知账，不能当成真实传感器探测结果 |

每个参数应有单位、时期、作用范围、来源、统计口径及未知值。三十年代红军、抗战时期航空、高炮与现代导弹不能共用装备表。史料中的总兵力/战役伤亡不能直接均摊到每回合。没有依据的数值保留未知；教学假设独立标明，后续用历史结果做区间敏感性分析。

## 本轮航空过程与边界

`backend/afsim_air.py` 登记 `afsim-air-teaching-1`，仅用于 AJ18 湘西会战、AJ19 缅北滇西反攻的**局部教学想定**。显式合成红方8架、每批2架，蓝方不配置飞机；这不是历史架数复原。防空损失率、人员效能、油弹工作单位为合成参数，并随版本摘要保存，不能静默修改已有存档。其他43个目录场景不会因此获得航空能力。

链路为：选择地面请求单位及敌方目标 → 校验权限、禁火、航空资源和回合窗口 → AFSIM延迟创建航空任务 → 原生 AIR_MOVER 执行入场/目标/返场航路 → 到达时复核目标位置 → 防空响应及打击，或目标脱离导致中止 → 原生回传逐阶段时间、位置、战果与航空库存 → 校验完整性、账目守恒后原子提交。

目标航空任务消耗独立航空油弹，不扣地面单位的3份射击弹药；旧版无目标 `air_support` 仍为兼容旧回放的补给干扰规则，不可当成航空打击。人员与装备效果分开，实际损失受目标剩余量限制；任务期望效果与实际总损失分别展示，不能把多个任务期望效果直接相加当实际战损。

保留既有想定的版本及目标标题，不修改旧存档定义：航空型目标仍由“控制目标区连续两轮”判定。标题里的“影响到货”属于旧干扰规则；新目标空袭通过人员/装备损失间接影响控制权，不自动降低全体敌军补给。真实空中遮断需要运输路线、车队、破坏持续时间及修复能力，应作为后续独立任务模型，不能沿用无依据的全局补给减半。

当前支持回合内完成返场；窗口不足直接拒绝，不虚构到达。中止仍耗油、产生架次，但不投弹、不造成战损。取消、缺失返场记录、引擎失败不提交世界与资源变化。任务、航空账与轨迹随已有战局检查点保存，DSH按需读取，无需把全量战局放入上下文。

未实现：真实机场/转场、跨回合在途任务、气象、DEM遮蔽、雷达与空战、弹道/弹药型号效能、分类真实装备表。这些需要先补数据，再扩展模型，不能用本轮合成打击替代验收。

## 前端改动简报

沿用 CommandCenter 的单位选择、动作下拉、敌方目标选择和自然语言草稿确认，不另建指挥窗口。AFSIM 的航空支援必须选择目标，禁火同时约束空中打击。原地图新增可辨识的航空任务虚线与目标点；在现有分析台加入“航空任务”页签，展示航空资源、事件时间线、减员及飞机损失，注明“教学模型”，避免新增顶部面板挤压地图和执行证据。任务时间是本轮内偏移，避免与历史战报绝对时刻混淆。所有输出使用文本节点/Vue插值，避免模型或单位名称注入HTML。

宽屏及窄屏应检查面板滚动、目标选择、地图落点与航路；后端需验证真实引擎事件、中止/资源不足、多任务守恒、存档恢复、反事实只读及DSH读取最新战果。
