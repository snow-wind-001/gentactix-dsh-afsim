## 问题与实现

资源守恒不能保证命令有效。此前DSH候选仍可能待命却移动或开火、改变射击目标、实际位置偏离已提交目的地，或在没有对应来袭交战时增加战斗减员。一个旧几何重试测试甚至同时提交了待命命令和炮击事件；现已将该测试修正为真正获准的炮击并声明弹耗，没有放宽几何检查。

`backend/dsh_simulation.py`在现有命令、位移预算、射程及资源校验之后核对结果，记录`dsh-command-effects-1`。可行动单位必须明确命令；非移动动作保留既有10米位置容差，移动结果须对应本轮位置命令并受预算限制。失能后的部分移动只允许处于已提交路线范围。交战须对应射手、阵营、动作及目标，事件位置须接近目标本轮起止位置；新增战斗减员须有该单位的对应来袭事件。允许射击没有杀伤，不设伤亡下限。

已提供的公开决策与结构化过程事件也须对应实际命令。来源标签、编组角色和原生内部毁伤余量不能由模型改写；提示投影不再发送原生内部回执和余量。人员装备的数值变化由宿主标注为DSH估计，不冒称AFSIM执行。沿用既有一次候选反馈重试，错误整轮拒收；没有新增战斗执行器、代理循环或自动纠正结果。

原生AFSIM计算和冻结火力参数保持原版本。上述校验约束模型结果的一致性，不会把历史总伤亡作为每轮必扣配额，也不证明新结果已经完成历史效能标定。

## 实际双引擎对照

沿用真正DSH构建的马良山局部身份，红方第571团与蓝方3RAR。1600/500人、双方距中心约300米及其他计算参数均为显式QA估计，不是考证完成的史实部署。每轮30分钟。

| 执行 | 实际命令与结果 |
| --- | --- |
| AFSIM第一轮 | DSH实际调用态势与史料工具规划，红方北移约100米、蓝方待命；一次运行3步，19053tokens，约20.4秒。 |
| AFSIM第二轮 | 双方人工确认射击，跳过额外模型规划；双方各14个原生火力周期。红方减员12（阵亡估计3、负伤9），蓝方26（阵亡估计6、负伤20）。 |
| AFSIM只读分支 | 从相同决策前状态撤掉蓝方射击，红方战斗减员变为0，主局逐项不变。 |
| DSH独立第一轮 | 红方按指定地图目的地移动，蓝方待命；没有交战或战斗减员。 |
| DSH独立第二轮 | 仅蓝方获准射击，红方待命；红方新增减员18（阵亡估计4、负伤14），蓝方仍0。 |
| DSH独立第三轮 | 清除人工接管后，红方自主射击、蓝方自主移动；公开决策与实际命令对应，蓝方新增减员12，红方保持18。时钟准确推进到05:30。 |
| DSH只读分支 | 从第二轮决策前状态改为全部待命，没有新增战斗减员；第三轮主局不变。 |

真实命令、账目、来源与分支共20项检查通过。DSH三轮分别约65.9/88.3/214.1秒，19753/22324/34010tokens；均一次候选通过，没有降低思考强度或为了结果重建战局。模型分支仍受采样与模型先验影响，不能解释为已经识别真实历史因果效应。

## 页面恢复与验证

真实复现了重开运行中页面后推进按钮仍可用、取消按钮缺失的问题。现复用已有进度轮询与原生取消：恢复时确认后台状态，运行中禁用冲突操作并显示取消，结束后刷新权威快照。只有匹配操作ID的成功或失败记录才显示确定结果，缺记录保持未确认；网络错误不当作任务完成。

真实取消测试8项通过，DSH原生运行时确认取消，主局及时间均未提交改变，操作按钮恢复。取消的原始运行时诊断仍可能显示`finish_reason=aborted`及连接检查建议，应与界面“已取消”状态一起判断，不能把它当成战局成功提交。

离线全量66/66组、732项unittest、0跳过，包括新增23项命令效果回归及2项进度接口回归；相关103项单测通过。前端类型检查与生产构建通过，仍有既有大分块提示。证据与失败记录保存在`.cache/qa/dsh-effects/`。测试驱动的选择器、已消失提示和切换后页面状态假设错误也保留，与产品故障区分。

1440/900宽度、双引擎真实页面共30项检查通过：当前人员和减员对应实际账、原生火力周期仅在AFSIM显示、两方最新决策/执行回执可读，没有页面横向溢出或脚本异常；最终截图已查看，瓦片分别24/16张全部加载。没有使用接口替身。
