# DSH累计账观察与表格复核

本次改进AFSIM已提交数据的读取与展示，不改战斗内核、历史资料或既有对局结果。DSH继续负责决策和解释，AFSIM继续负责已登记过程计算；完整状态留在宿主检查点，前端仍使用现有地图和工作台。未安装替换、打包或上传。

## 现有工具的累计账查询

在原生`get_afsim_changes`增加可选`mode=aggregate`，默认`changes`明细合同不变。例如：

```json
{"mode":"aggregate","since_turn":0,"through_turn":16,"limit":16}
```

沿用原生注册、角色工具可见范围、JSON-RPC桥、只读上下文和取消机制。没有新增工具循环、模型传输、执行器或PTC。`backend/afsim_summary.py`仅归并已提交变化，不执行交战、不读取完整快照生成结论，也不产生新的伤亡。

聚合按轨迹中“方别＋名称”分组，每页最多16个发生过变化的单位；完整登记名单仍由观察工具提供。人员、分类装备和库存保留首末已知端点及净变化，缺载保持`null`，明确端点不连续。装备可用、待修、毁损分别显示；旧未分类装备以`unclassified:名称`保留，不推断武器类别。

累计火力、射击尝试、位移、维修和分类到货仅取对应轮的有效回执。每项提供已知累计、已知回执数和缺载数，明确零与未知不同。重复轮次或重复同名变化拒绝聚合，改读明细核对。缺轮和未知时钟另行报告，配置步长不能补作实际历时。

查询版本绑定时间范围、模式、当前世界及变化记录。两种模式均沿`next_args`读完；不能混用版本，也不能把第一页当作全量。字段投影不等于原始证据缺载。需核对某轮、未知值或不连续端点时，仍可读取同范围明细。

## 修正弹数与兵种口径

原生`shots`在直射中计火力周期，在间瞄炮击／压制中计炮弹。新增聚合项`artillery_shells_fired`分离间瞄炮弹，小武器使用`small_arms_rounds_estimate`；原始计数保留，不能相加称为统一总弹数。库存端点差、实际发射与轮末到货分别核对。

`active_fire_s`是该单位自身有效火力时长，不是目标承受火力时长，跨单位相加也不等于战役历时。共享`fire`动作或`ammo`工作量不代表兵种相同；分析按观察中的`type`和`formation.role`辨认。

## 前端与回归

发现现有安全Markdown子集不支持表格，模型数据表被显示为竖线文本。现增加语义表头、可横向滚动并键盘聚焦的数据表，支持转义竖线、围栏代码及既有行内格式；先转义HTML，不解析任意HTML或新增脚本权限。未增加依赖。列数异常的行保留为文字，不静默丢掉数值。

先写失败回归再实现：聚合13项，Markdown脚本覆盖表格、恶意HTML、转义竖线、旧格式、异常行和代码示例。最终62/62组、640项unittest、0跳过；前端类型检查和生产构建通过，Vite仍有单包超过500kB提示。真实前端1440/900宽度19项通过，表格内容、表头、局部横向与键盘滚动正常，截图已查看，无接口替身。

证据在`.cache/qa/change-summary/`：红／绿回归日志、`aggregate.json`、`native-tool-calls.json`、`natural-answer.json`、`semantic-review.json`、`result.json`、浏览器截图及最终离线清单。原用户六份存档、密文和密钥保持不变，`AGENTS.md`未改。
