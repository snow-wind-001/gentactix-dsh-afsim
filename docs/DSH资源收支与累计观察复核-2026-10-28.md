## 已复现的问题

前次马良山局部QA关闭AFSIM后，两轮移动、待命均保留80粮食；此前只检查库存范围，没有核对收支。旧DSH账又将粮食净增加量写成到货量，无法区分“未消耗”和“消耗后得到补充”。

真实原生复盘还曾用本轮每单位2粮食描述两轮总消耗6。仅把当前余额传给模型无法提供完整的毛到货与费用证据。因此需要同时修复候选验证和原生累计观察。

## 原有执行结构保持不变

AFSIM仍通过现有DSH原生插件执行封闭WSF、产生状态与回执；DSH负责命令和解释，Vue/Electron保留地图和控制界面。关闭AFSIM时，DSH提出运动、损失和补给估计，程序校验候选与目标，没有调用Python战斗执行器，也没有新增模型循环、SDK或通用工具传输层。

`gentactix/resource_accounts.py`保存原有每行动粮食需求：移动4、其余2工作单位。现有Python兼容规则、两套WSF编译入口和DSH候选验证读取同一标量规则，当前系数未改。它是教学工作量，不是按人数或小时标定的真实口粮；不能据此声称完成后勤历史标定。

## 候选收支契约

新DSH候选必须带`resource_ledger.version=dsh-resource-ledger-1`及双方全部单位的账项：

| 字段 | 含义及检查 |
| --- | --- |
| `delivery` | 本轮估计毛到货，每份同时含1粮食与1弹药工作量；受既有行动、容量和仓库余额上限约束 |
| `food_spent` / `ammo_spent` | 显式消耗，与候选期末库存核对；本轮射击不能使用轮末新到弹药 |
| `supply_status` | 只能为未切断、已切断、未知；“未补给”不是连通状态，估计来源另由宿主标注 |
| `received` / `spent` | 燃油、备件、耗材、炮弹和防空弹药的分类到货/消耗；空对象明确声明各类为0 |

逐单位期末必须等于期初＋到货－消耗，仓库按同源所有单位毛到货合计扣账，不能重复支付或凭空补仓。分类收支核对本方仓库；摩托化实际位移还要满足既有燃油预算表达式。无粮可耗时不虚构扣粮，更不自动补死亡人数。原生执行回执和内部毁伤余量不得由DSH候选伪造。

验证只接受或拒绝模型候选，不替模型改库存。错误进入既有一次反馈重试；两次仍错则不提交战局或推进时钟。旧保存局不补写收支，也不追扣此前缺失消耗。只读反事实沿用同一契约并保留模型随机性说明。

## 有界观察与前端

既有`get_afsim_changes(mode=aggregate)`新增每单位`logistics_workload`：累计毛到货、粮食/弹药工作量消耗，分别保留来源、口径、已知项与缺账数。缺账不补0，旧DSH净增加量不累计成毛到货，重复账拒绝求和。完整账仍在宿主，不把各回合完整战局全部塞回模型。

“目标与运行”表将到货、消耗、余额分列，支持键盘聚焦和局部横向滚动。“保障”明确区分新DSH估计收支、旧净变化记录和原生回执；过期或跨引擎原生执行字段不再显示为本轮结果。新估计收支校验不等于运输过程已验证。

## 当前边界

资源守恒与已知行动预算不证明道路、搬运、交通线控制、卡车吞吐和补给时序均有足够历史依据。现有原生运输以配发运输单元为基础，徒步编组的人背肩扛能力仍未单独标定。仓库遭袭的独立损失、详细搬运过程及分用途燃油回执也仍有缺项；燃油净减少不能全部归因于机动。

同窗口兵力、兵器、地形、增援及损失标定仍不足，完整历史业务验收保持0/45；29场仍缺当前格式的具名初态。不能将本次收支检查改称全战役、全后勤或自由文字全部可靠。
