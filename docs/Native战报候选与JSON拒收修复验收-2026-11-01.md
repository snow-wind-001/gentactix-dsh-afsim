## 故障与实现选择

原`d9d0a7cae06e`调用在Native日志中以`completed`结束，但公开答复1198字符，报告及对象未闭合，输出975 token，远低于配置预算。不能诊断为断网或token不足。解析原来位于效果候选纠错块之外。

先按TDD添加类型化`JSONOutputError`和一次有界恢复。真实`7cda77706dab`的T+2再次自然发生坏JSON，恢复后只推进30分钟、只扣一次粮。取消后的T+3重试却连续返回坏JSON，并发生DSH原生compact；世界保留T+2。**重试不足以消除自由文本JSON的脆弱性**，阶段源码及失败均保留。

最终增加DSH原生`submit_turn_report({preview_hash, report})`：

1. 复用`preview_turn_effects`校验效果，取得当前世界、操作、候选及结算指纹。
2. Cordis插件从当前Agent的公开`snapshotEvents()`选择对应预览调用／结果，只向宿主传这一对证据，不传私有推理或聊天，不让模型再次输出全部效果。
3. 宿主验证预览与完整正文，返回只读报告候选回执。没有新状态缓存，不执行动作、扣物资或提交世界。
4. 运行正常完成后，宿主从本次公开工具轨迹读取报告，重新验证效果后沿原事务提交。最后自由文本不再充当Native数值结果载体。

`aborted/error/max-tokens`、取消、跨操作证据、正文篡改及伪造指纹仍拒收；报告提交后又有新预览须重交。空最终文字只有在已有完整有效Native报告时才可继续。旧JSON协议仍严格解析并有界恢复，不补括号、不猜状态。前端恢复显示等待色、明确文案并保持取消可用。

实现位于`backend/turn_preview.py`、`harness_engine.py`、`dsh_simulation.py`、`main.py`及`plugins/dsh-gentactix`。复用原生注册、事件、桥接、角色限制、取消和compact；仍是Native，非PTC。只有DSH过程engine拥有报告工具，问答／分析及AFSIM角色没有该权限。
