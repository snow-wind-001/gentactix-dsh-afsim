# 3.5.0 史实基础、想定编辑与逐场过程审计

本版已替换本机AppImage及应用菜单/桌面入口，未上传GitHub。实际运行的窗口、API及包内冻结后端均为3.5.0；原有7份会话文件、模型密文和Vault密钥校验一致。

## 最近对局的问题

最近张家口局部对局没有`mission_id`，实际是AFSIM仅运动分支，只能hold/move，不会计算交战、人员装备战损或补给消耗。蓝方5单位连续4轮均因漏交命令被默认待命，共20条`default_hold`。城郊机枪阵地的经度40.792重复了纬度，从初始化起已错误；不是外部模拟器移动造成。切换初态后仍残留合成教学描述，也继续影响了模型。

本版增加战区粗校验：已知战役参考点200公里外的单位拒绝提交，不猜测替代坐标；派生演习部署另受局部10公里边界约束。旧存档可读取，异常状态续推在调用模型前拒绝。该检查抓字段/大陆级错误，不证明历史阵地位置精确。

DSH规划必须覆盖双方所有未由人工或单位Agent覆盖的可行动单位，包括带公开理由的hold。遗漏只允许一次反馈重试，仍遗漏则不执行、不提交；明确守备、停火或撤退仍是合法决策，不强行制造交战。

## 三类用途

| 类型 | 当前能力 |
| --- | --- |
| 历史战役回溯分析 | 45项、266个来源事件帧及只读分析；缺载部署、每单位指挥记录和逐帧损耗保持未知 |
| 历史战局推演 | 完整历史初态、分期部署和战役专用阶段机制尚未接通；界面明确标为运动预览或模型叙事，不自动替换成合成演习 |
| 合成教学演习 | 从史料参战单位参考派生，经DSH skill配置、地图编辑、AFSIM装载验证再创建；数值与部署仍为演习估计 |

逐场审计发现原45份CA模板都是6编组、30分钟、8回合；15个长征模板全部套用突围目标，包座、直罗镇、百丈关等不能因此表达各自历史过程。四渡赤水多渡口/转向、上甘岭地表/坑道分层、受降权限与地方服从等机制仍缺。完整45行过程、缺口与实施顺序见[逐场审计](../历史过程逐场审计-2026-10-27.md)，不是45场完整历史有效性验收。

## 从史实基础创建派生演习

1. 选择战役和“合成教学演习”，读取关联来源、参战部队/隶属参考和缺载项。历史实际人数、装备可用量及战术位置未知时仍保留未知；种子的局部数量单独标为估计。
2. 输入变体需求，DSH经现有Cordis原生工具实际读取项目skill、读取战役基础并校验结构化配置。版本和史料摘要由宿主绑定，减少模型复制只读摘要造成的错误；沿用high与65,536预算。
3. 增删派生编组，每方1–12个；编辑人数、装甲/火炮/防空/工兵/运输五类装备、粮弹工作量、炮弹、防空弹药、燃油及疲劳。选择单位后在地图点击部署位置，界面自动收起遮挡并返回配置。
4. 修改会使旧验证失效。重新由封闭编译器生成WSF并真实装载，创建时校验配置及规则摘要；规则更新的旧草稿需再次验证。模型不直接写WSF或权威战局。

构建工具使用`read_scenario_skill`、`get_scenario_basis`、`validate_scenario_configuration`，通过既有DSH会话、工具事件、角色预算和原生取消运行，不使用PTC，也没有新增模型传输协议。项目skill适配上游`afsim-skill`的已验证模板原则；上游skill及许可证随包提供，私有AFSIM程序仍由本机工程目录提供。

验证草稿存放在会话目录旁`scenario-drafts/`，父版本与DSH调用记录可追溯；创建后的战局含来源参考、估计属性、参数配置及构建证据。当前并非任意武器型号、传感器或地形网格编辑器，射程和目标仍使用已登记规则。完整历史初态、精细阶段图及全部逐场策略验收是后续工作。
