# 万家岭会战窗口准入与验收

## 范围与架构决策

本轮推进主规划K02／K03的窗口准入分项，不宣称完成会战全程。现有累计选择包含10月16日后的第61师，又以第123联队替换第106师团，不能直接作为6—10日同场初态。新增可选窗口绑定初态1.3.0及内容摘要，旧版本、默认入口与已有对局不变。

论文[《万家岭战役述评》](https://www.krzzjn.com/uploadfile/2018/0604/20180604092232868.pdf)（郭代习，1996年第2期，111—126页）已核印刷118—120页及既有116—121页定位。它是研究论文及转引，未核中方电报原件、日军联队日志。行政隶属、临时统一指挥、调令、启程、到场、接敌分别记录；不得从时段命令推定精确部署。

## 前端与工具接口设计

- 入口复用`HistoricalScenarioComposer`：编制范围选择会战后，可选累计序列或固定版本窗口；其余战役继续原流程。窗口固定史料版本与开局阶段，其他选择须先退出窗口，避免隐式替换。
- GET basis和POST build共同传递窗口ID／版本；返回来源快照、窗口边界、逐单位投入范围、参考方向、排除身份和余部声明。加载、失败、配置草稿、已验证状态延用现有控件，键盘可通过具名select操作。
- DSH复用原生分片配置工具，不新建状态账。完整只读窗口保留在宿主，模型只接收固定摘要及当前片单位的投入范围，防止每次重复窗口全文。参数提交不能移除或替换窗口。
- 阵位、兵额、装备、到场、补给和效能缺载时继续为null；用户／模型必须显式填写估计。来源节点只作参照，开放模式不按历史日历强行移动、补兵、撤退或结束。
- 配置绑定携带冻结窗口，恢复只校验内联快照，不依赖后来注册表。未知余部不得用零或已列下级静默代替。

## 实施与检测顺序

1. TDD保存缺失窗口模块的失败前态；验证39个来源身份各有处理方式、22个候选不重叠、后续第61师排除、有机123联队与106聚合不双计。
2. 接入参数模板、领域校验、正常API和原生分片工具。错误版本、阶段、摘要、人数缺填、父子双计、窗口丢失和过期revision必须拒收且无写入；旧累计79单位回归继续通过。
3. 绑定前端选择和提示，做类型／生产构建及真实浏览器选择检查；加载错误可恢复，不能把“可生成参数”显示为“历史部署已核实”。
4. 明确QA数值假设后验证双方实体创建、冻结恢复和既有计算器入口；真实DSH生成、两后端全窗运行、地形／补给／历史效能标定分别记录，未执行保持`not_run`。
5. 相关回归通过后运行全量根验证与上下文退化；核对保护指纹和资料生成一致性，更新主规划、矩阵与逐场状态。

## 尚未完成的会战责任

窗口准入不解决真正场外状态、跨日粮弹标定、实时细分／合并、连续临时配属、道路／LOS、多仓保障和历史战损。第149联队6—10日持续在场与临时指挥结束日仍未知；加入候选必须说明其投入估计。第91师、预6师原文为“各一部”，不按完整师满编计量。两种后端全窗口及45场逐场历史验收尚不能由此分项替代。
