复核日期：2026-11-01。对象是当前工作区源码和本地资料，不是GitHub或本机安装版。任务是判断既有会战改造推进到哪一步、45场资料还缺什么，并将后续工作落实到[主规划](会战级多层编制与分合兵改造规划-2026-10-31.md)和[检测矩阵](会战级改造验收矩阵-2026-10-31.md)。

**这是代码修复前的只读审计快照。** 随后已执行Q01代码修复、真实Native／前端／取消及冷恢复，最终116组／1272项；见[后续验收与剩余解释问题](原生过程预览与战报结算验收-2026-11-01.md)。下文17项预览／1261项门禁及“未运行”描述保留审计时点含义，不作为修复后现状。

此后[万家岭1.3.0资料增量](万家岭会战资料与后续过程增量验收-2026-11-01.md)使目录增至56版本，取得117组／1283项及真实来源查询／27帧回放证据。来源节点增加不改变默认版本，也未完成数值会战部署、实体到离场或历史标定。

## 1. 结论

**需要全目录审核与计算契约升级，不需要全目录重写史料。** 当前已经有可复用的多层指挥、互斥计算分队、持续任务、目标图和单世界阶段基础；主要缺口是把这些能力与真实的分时投入、部署、资源及过程连接起来。尚不能认定全部场景均能完成所设计的会战功能。

目前“大名单”可以生成，“多个方向同时作战、资源与指挥连续、决策影响结果、历史效能得到验证”仍须逐项建设。扩大单位数量、增加上下文、提高最低战死人数，都不能替代这条链路。

## 2. 审核范围和证据强度

本轮实际执行：

- 调用现有只读`campaign_readiness_audit.py`遍历45场全部55份初态，区分默认／最新、局部模板／累计候选／事实缺项。
- 查看事实与参数绑定、编制覆盖、阶段事件、组织／持续任务、单世界阶段、旧续接、两执行后端、DSH原生工具及前端接点。
- 补查各最新版本的下级覆盖、事件、关系；读取抗日战争／长征编辑源及生成器。
- 运行三项生成一致性检查和当前源码的全量离线门禁；最终结果另列第8节。
- 留存814个相关源码／资料／测试文件的输入指纹，用于确认本轮审计没有改动它们。指纹只用于本轮范围核对，不要求每份史料为教学用途额外制造校验流程。

本轮**没有**重新联网核读所有原件，没有运行45场真实模型全程，没有把现有QA估计情景升级为史实，也没有测试或替换安装包。文献中的人物、数值和坐标若没有本轮原件核读，不因此获得更高史料等级。

证据位于`.cache/qa/campaign-review-2026-11-01/`：`catalogue.json/csv`、`extended-catalogue.json`、`input-manifest.json`、独立`offline-gate/`及文档修订前副本。不读取用户密钥或对局；不启动或中断用户服务。

最新45份中仅万家岭登记了上述显式覆盖和事件关系。其他档案缺此结构，不等于史料没有提到过程，而是尚不能由程序按该契约使用。事实字段全部未知，也不等于语料没有数字：总兵力、全役伤亡、后续投入等通常不能直接作某日某团的实力。

编辑源盘点：抗日战争52行部队、124行时间线、60行数值、55行缺口、46条来源；长征45／116／52／49行及37条来源。条目数不是独立原始档案数，三个生成检查通过也不证明每个断言正确。现有49份语料Markdown包含说明等文档，不按文件数估算战役完备率。

`historical_initial.readiness()`当前明确固定返回过程未认证。因此“0个已认证”不能当作本轮实际推演0/45成功；同样，模板能返回JSON或预期`ValueError`不能当完整业务通过。模板健康检查只发现非预期异常，本次没有此类异常。

## 4. 架构实况

| 层 | 已具备 | 当前边界与直接影响 |
|---|---|---|
| 冻结史料／参数 | 独立事实、估计、来源和版本，目标绑定已有跨版本保护 | 还没有全目录完整编制、部署、资源和历史效能基线 |
| 编制与指挥 | 多层临时任务群、已有下级分合／转隶、行政与当前指挥分页 | 主要是组织关系变化；运行中细分、历史改编和未列余部不能自动生成 |
| 任务与目标 | 双边多轴目标、依赖／保持、持续任务等待／释放／回执及人工优先 | 目标评分不自动生成协同命令；单方、破袭、组织存续等不能硬套双边图 |
| 时间与阶段 | 可选同世界阶段链已实测QA十阶段、原任务和时钟间隙 | 同一执行集合的连续不证明退场重返、场外补算或实际历史投入 |
| 旧阶段入口 | 冻结相邻阶段和守恒继承，拒绝无法登记的重编或跳时 | 仍限8次续接、拒绝新目标图；这是受限兼容路径，不能与新链混淆 |
| AFSIM过程 | 外部原生执行、登记的聚合火力／运动／工程／航空及回执 | 域规则是项目建模内容；不会自动补齐历史场景。原生代码有按阵营取首仓和阵营分类库存池的假设 |
| DSH独立过程 | 原生会话／工具、结构化候选、守恒校验、取消、事件和分支 | 仍逐轮携带全体单位，要求全体效果／动作／决策。上下文上限不是分层计算方案 |
| 报告与归因 | 公开决策与回执、已知错误筛查；新增只读过程预览与结算摘要 | 新预览已改最终答复契约，真实链路尚待验；语句筛查不能证明通用语义正确 |
| 前端 | 军标、可折叠工作台、多层树、地图目标、任务预览及进展面板 | 还须检验层级缩放、区域展开、方向／战线、场外单位和百单位列表；本轮未新跑浏览器 |

DSH当前是**Native原生工具模式，非PTC**。`plugins/dsh-gentactix`注册领域工具，`harness_engine.role_policy`按角色及操作限制，宿主持有状态；`dsh-afsim`负责受限外部接口。这个分工适合会战化，没必要为追求“智能体数量”另造运行时或赋予模型任意改状态能力。

`scenario_assembly.PAGE_SIZE=4`及串行分片是可定位的生成成本；`dsh_simulation.prompt()`保留全单位视图、要求`unit_updates/resource_ledger/decisions`全覆盖，是另一条上下文／输出成本。AFSIM卸载物理过程后仍须精简观察和决策频率；不能笼统承诺引入外部引擎便会提速多少。

## 6. 是否所有资料都要细化

**全45场必须更新范围、缺项和准入记录；内容按用途与模型细化。**

- 保留：有可靠出处的历史叙述、原始统计口径、来源冲突、时间精度和旧冻结版本。
- 全场补查：部队身份及有效时段、行政／作战关系、投入一部还是全体、下级覆盖、到离场、初态资源和目标承担者。
- 按类型补查：大会战多方向与预备队；渡河梯队／吞吐；游击根据地存续；铁路破袭／修复；坑道表面与地下；受降授权／登记；古代兵种与相对时钟。
- 明确估计：史料未载的局部人数、可用装备、库存、部署和效能参数，登记范围、依据及敏感性。不能把用户同意估计理解为允许把估计写回历史事实。
- 保持未知：无法支撑的精确钟点、坐标、团营番号或日方伤亡，不因推演需要制造确定性。

资料编辑采用单向生成，避免JSON、CSV、语料各改一份造成三种真值。冻结初态、编辑源和计算参数使用稳定ID映射，改史料不静默更改已有对局。逐场具体缺口及B0—B6批次已写回[45场清单](会战级资料逐场清单-2026-10-31.csv)。

## 7. 执行与检测的最小闭环

详细依赖和代码接点见主规划第7节。本轮明确下一顺序：

1. Q01新原生预览真实验收；原T4／T7／T9战报失败按旧前态只读重放，检查毛收支和同轮目标／阶段。
2. 万家岭完整声明窗口的资料与目标／任务绑定，继续明确局部与完整范围。
3. E04-B实体退出重返、场外消耗、跨阶段在途和有损重编；同一世界连续。
4. E05多仓运输、独立指挥通信及地形／通路；断补给、断联、阻援构成干预对照。
5. E06粒度／步长与兵种效能，历史训练与留出分开。
6. 武汉规模和前端流程，随后按B3—B6逐场推广，不能由试点替全目录签字。

每个工作包需要：输入版本和范围、正／负例、实际执行后端、资源及命令前后账、结果判断、失败保留、恢复结果和未测项。真实模型预算与思考配置沿用用户设置，不降思考、不换模型、不用夹具冒充。取消／失败必须无半提交。

完整会战验收至少核查：决策干预产生有因可循的变化、人员装备与库存连续、供给约束行动、双方每个活动单位有动作或等待原因、程序能判目标、三用途边界正确、两引擎各有证据。教学“合理”与历史“准确”分开评定。
