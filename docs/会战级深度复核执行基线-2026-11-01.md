## 1. 总体判断

**45场都需要复核可计算资料和能力声明，不需要全部重写历史正文。当前具备局部过程内核及部分会战组织能力，还没有全目录完整会战能力。** 下一步重点是将分时投入、真实下级、连续实体、资源和任务连接起来，不能只扩充名称、图标或上下文。

当前的“小单位化”有四层原因：

1. 默认入口多是某日、某渡口或某阵地片段，直接以它代表全会战就会缩成两三支部队。
2. 来源树含上级、支援、后续投入和累计参战。当前筛选会移除已列下级的祖先以避免双计，但缺失余部并不会因此变成已完整下沉。
3. 生成器只允许配置选定演员；把指挥部当步兵、把未知团营编出来补数会破坏来源和守恒，不是可接受的扩容。
4. 现有组织分合能改变指挥关系，开局划分能分配计算分队；它们都不能代替运行中有损细分／合并、到离场、道路展开、协同和保障网络。

因此改造对象包括资料、计算契约、运行过程、DSH观察和前端，不是单独一个“大兵团显示”开关。

## 3. 当前架构与可复用边界

主产品路径是Vue／Electron → FastAPI → 宿主世界／命令／检查点 → DSH Native与可选AFSIM。`app.py`保留Streamlit入口，Cloudflare另有部署包装；不能用旧Streamlit说明推断桌面新功能已覆盖。

| 层／接点 | 当前可复用能力 | 尚缺或受限部分 |
|---|---|---|
| `historical_initial/links/operations/campaign_scope` | 来源冻结、身份树、部分阶段关系、局部／累计范围、余部声明 | 全目录分时编制／部署／实力；未知余部计算身份及可核投入 |
| `initial_command/force_organization` | 行政与当前主指挥区分；临时群、统一上级、转隶、成员分页 | 运行中物理粒度变化不由此实现；多支援能力仍需共享占用 |
| `formation_parts` | 开局互斥分配；V2每父最多32分队、每方最多256叶子 | `expand()`明确不拆运行中世界；容量校验不等于256单位性能通过 |
| `commands/force_tasks/force_task_execution` | 单位控制、地图目的地、分工预览、持续任务依赖和实际回执 | 每叶每轮一项主动作；人工接管目前阻止持续任务自动重接，临时退出恢复需另定语义 |
| `campaign_plan/campaign_lifecycle` | 最多64目标节点；2—256阶段的同世界里程碑、双边结果和恢复 | 可选契约尚未迁移全部默认；阶段链不等于参与／改编；单方和特殊目标还需适配 |
| `phase_continuity/phase_routes` | 旧相邻阶段冻结与有约束继承 | 仍有8次续接限制；与新同世界链区分，不能直接删除限制绕过模型边界 |
| `unit_participation`草案 | 单世界后方待命／重新投入的领域校验及状态草案 | 命令入口失败，生产调用不存在；不是场外补算、退役或换装；尚未业务接通 |
| `afsim_turns/afsim_combined` | 命令经原生引擎运动和项目登记规则，回执后宿主评分 | 多处仍按阵营取首仓；仓、运输、通信和支援不是完备会战网络 |
| `dsh_simulation` | 原生工具候选、守恒校验、同操作只读预览、拒收和取消 | 提示仍携全单位；要求双方效果账与决策全覆盖；不能只调大context解决规模 |
| `terrain_process/crossing_*` | 有限线障碍、直路走廊和登记渡运／通路 | 无隐式DEM、通用LOS或道路寻径；点状实体不足以表示完整正面和纵深 |
| `turn_settlement/reporting` | 毛收支、轮初末、目标阶段与实际回执归纳；已知错误筛查 | 自由解释仍有X20；自动筛查通过不代表全文事实正确 |
| `causal/afsim_comparison` | 公开决策、几何干预与另行实际引擎对照入口 | 几何归因不重算伤亡／弹药／胜负，最多12个位移和前4个有影响交互；不能冒充完整因果分析 |
| `session_store`与回合提交 | 检查点、恢复校验、原子替换；回合候选保存后更新活局 | 新转换、参与状态和在途账也必须接同一路径，不能在工具内提前写局 |

DSH当前采用**Native领域工具模式，非PTC**；原生插件已有工具注册、角色限制、事件、取消、fork和子工作单元入口。合理方向是扩展领域契约并复用这些能力，不另造智能体运行时。宿主世界才是状态权威，DSH会话与compact不保存第二套人员库存账。AI公开依据和工具轨迹足以复盘，不要求私有思考过程。

初始化成本也有明确接点：`backend/scenario_assembly.PAGE_SIZE=4`，79演员至少需要20个演员分片，另有全局、校验和重试。运行成本还含模型、工具、原生过程、校验、存档和渲染，必须分项测量后优化；不据外部引擎名称承诺固定提速倍数。

## 6. 目标架构与实施原则

保留现有链路：来源断言 → 冻结身份和分时投入 → DSH Native配置草案 → 宿主准入 → 唯一世界 → 方向／编组任务 → 下级命令 → 所选后端过程 → 宿主守恒、评分、阶段、提交 → 地图、公开决策、战报和反事实。

必须分清五类身份：来源单位、持续实体／根账、互斥计算分队、当前任务群、命令／执行回执。它们可以引用，不能混用；名字只显示，不作为运行中改编与控制的唯一键。独立对局各自拥有世界，只有明确同会战连续链才继承实体，不把另一存档的兵力拿来扣账。

分合兵分三种：①现有叶子的组织分合；②当前实态的计算细分／合并；③有依据的历史改编／补充。前者只改指挥，后两者需要转换账。上级和显示聚合不产生新兵力；异地组织合编不瞬移，运行中物理合并不采用平均坐标制造新交战平台。

参与状态必须先区分：未到场、在场、撤出途中、同世界后方待命、实际场外、返场途中、退役归档；行动能力另由伤损推导。当前草案只覆盖其中一部分。后方单位仍可被打击，失能不等于不存在，返场不得补满。

DSH负责方案、任务分解、按需观察、来源解释和受约束干预；AFSIM负责所登记过程的实际执行；DSH独立后端明确标为模型效果估计。两者共享计量、守恒和接口契约，不要求逐人损失完全一致，也不把项目聚合规则包装成未经标定的历史事实。

## 7. 逐项执行与完成门槛

[主规划第7.2节](会战级多层编制与分合兵改造规划-2026-10-31.md#72-可执行顺序逐包出口与回退)给出K01—K12的接点、依赖和出口：**接入红例 → 全目录范围登记 → 万家岭完整声明窗口 → 连续实体和在途 → 运行中转换 → 类型目标与任务 → 保障／C2 → 地形 → 效能 → DSH及UI规模 → 武汉与逐场推广 → 独立交付**。

资料核读和通用领域TDD可以交错，不需要等待全部史料补齐再验证通用能力；真实历史验收必须使用相应已准入版本。每包保留失败前态、明确一个行为契约，再接两后端／工具／UI，不一次性扩大所有默认范围。

### 7.1 强制检测要求

- **守恒**：人数、装备和整数绝对库存误差为0；内部调拨抵消；归一化粮弹按冻结尺度换算；浮点误差按字段精度预登记，禁止以百分比误差容忍人员丢失。
- **连续**：有伤损退出、6小时／两天保障、真实返场、运输／渡运跨阶段、10阶段链、取消与冷恢复。必须区分纯领域手工后态、真实原生过程和真实DSH过程。
- **转换**：1/4/16/32表示下的整数分配、历史根账、冷却、疲劳、压制、损耗余量、任务与在途载荷都明确迁移；未知或不支持转换原局不变。
- **决策**：双方每个活动叶子有动作或具体等待原因；同前态至少两类相关单因素干预。无可作用路径可以没有差异，不硬造战果或因果百分比。
- **时间**：5/15/30/60分钟同总时长对照；物理时钟、报告和目标采样一致；开放模式以任务完成为主，历史日期不自动判败；严格回溯只约束来源确证节点。
- **历史**：同单位、同日期、同范围、同统计口径比较；标定和留出分离；不得通过最低杀伤或均摊全役损失拟合史实。
- **DSH**：Native真实工具轨迹、分页完整、compact后重取、人工优先、角色限制和取消；保持用户模型与思考设置，不用固定响应替代真实模型。
- **前端**：正常选择版本／范围／用途／引擎，地图选上级与下级、分兵、命令、执行、合编、阶段、保存和恢复；900／1440／1920宽，地图、树、任务、账目同revision。
- **规模**：16/64/128/256/512总叶子分档；64—128叶子至少100次连续提交。无中断与故障恢复分别报告；记录样本数、p50/p95/max、内存和日志增长。
- **交付**：定向回归、全部根回归、上下文退化及前端类型／构建；实际安装包另验，源码通过不能当安装版通过。

UI反馈p95≤200ms、无模型本地预览p95≤1s是待测产品目标，须注明硬件／规模。历史损失容差须依据统计口径、采样与数值收敛预登记，本次不虚构统一“误差10%即准确”的标准。

### 7.2 每场独立准入

45场各登记3用途×2后端共6个组合，即270个**状态格**，不等于预先要求270条相同物理流程。状态用`passed/failed/not_run/not_applicable`，不适用附原因。历史来源回放、数值历史回溯、开放过程和合成修改分别限定范围；仅显示事件帧不能取得物理战斗通过。

每格至少绑定来源、参数、规则、源码和模型版本，输入窗口及部署、命令、逐轮回执、资源与目标账、问题表、真实界面证据和冷恢复结果。完整声明窗口的历史过程、决策敏感性、模型解释和无中断稳定性各自签结，不能由单场试点替全部目录通过。
