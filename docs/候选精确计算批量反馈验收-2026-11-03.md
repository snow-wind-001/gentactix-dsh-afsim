# 候选精确计算批量反馈验收

本片针对真实第7回合中反复修订粮耗、疲劳、库存和位置的问题，改善DSH原生工具的只读反馈。它没有重写战役规则，也没有完成45场／270个完整历史窗口验收。用户模型配置、原对局、安装版及GitHub均未修改。

## 改动与计算边界

原预览通常只返回最先遇到的领域错误，模型修正后才能看到下一个。现在失败的`preview_turn_effects`和`amend_turn_effects`在保留原错误、拒收结果和候选引用的同时，附带`calculation_diagnostics`：

| 核对项 | 复用依据 | 适用条件 |
|---|---|---|
| 行动与公开决策 | 原有命令合并／优先级／合法性检查 | 使用实际生效的人工、持续任务与原生单位命令 |
| 粮食工作量 | `resource_accounts.required_food()`，与正式守恒校验共用 | 区分旧规则、时间保障、分队比例和定时补给 |
| 粮弹期末库存 | `resource_accounts.closing_stock()`，与正式守恒校验共用 | 到货、弹药消耗等仍为该候选的条件输入 |
| 目的地不一致 | 原有解析后命令与距离判定 | 不将桥梁排队、舟艇载运当作直接抵达 |
| 疲劳 | 原有`movement_feedback.travel()`与`fatigue_value()` | 按候选实际陆地距离和缺粮债；位置不成立时暂不给疲劳值 |

反馈含轮初世界、当前候选和操作的摘要、精确JSON路径、期望值及不能计算的原因。更新／账目重排时按实际索引定位，重复或缺失单位不猜测。定时补给账未通过时不能退回旧粮耗公式。修改行动、到货、位置等依赖后，旧反馈不再代表新候选。

诊断不返回补丁、修好的候选或下一世界，不调用战局执行器，不消费命令，不写状态。模型仍须显式提交修改，经过原有完整人员、装备、物资、火力、地形、时钟和目标校验；成功预览、公开凭证及正式提交路径不变。

共享候选Schema补充`fatigue/suppression/entrenchment/signal`整数类型，原0—100领域校验仍保留。沿用既有JS数值等价表示，不把1.5等估计小数自动取整，也不改变权威世界数值。原生插件描述与过程提示说明如何一次核对全部反馈；没有新增执行器、缓存或通用shell。

## 继续处理的真实问题

1. 本轮两次时间保障`demand`回执拒收、一次装填剩余秒数拒收尚无对应批量提示；补齐时应复用已有保障和火力校验方程，不另写公式。定时补给中已支持的粮耗查询不等同于完整保障回执覆盖。

4. 原生上下文整体复制、运行时完整轨迹体积和部分旧一次性审计脚本直接读取V1的问题仍在后续清单。
