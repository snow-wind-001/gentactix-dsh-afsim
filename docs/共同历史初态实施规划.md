# 共同历史初态实施规划

本规划承接全45场审计和用户的最新要求，不以局部教学模板替代历史战役。目标仍包括全部场景的AFSIM后台计算、DSH全局控制与观察，以及当前前端的地图和指挥功能。

## 数据契约

建立版本化`historical_initial`档案：战役、阶段、日期精度、真实单位ID/番号、指挥或作战角色、上下级、参战时段、部署区域、来源与未知字段。来源事实与计算参数分开；没有证据的实际人数、装备与精确坐标保持未知，不把3000人或教学工兵/运输配额带入历史档案。

档案必须保留覆盖程度：完整、部分、待整理。指挥部不是前线步兵，战役累计参战不等于开局到场，上下级不能同时按人员总量重复计数。新旧修订并存；已保存战局固定使用原定义和来源快照。

## 加载与执行

- 回溯分析与历史战局推演使用同一档案、同一阶段和同一初态摘要，不接受CA代表编组。回溯按来源事件约束过程；开放推演允许改变决策。
- 合成演习先显示共同历史基础，再显式派生、增删或调整局部编组。原始事实与派生参数分开保存。
- DSH与AFSIM选择不改变历史单位身份或初始来源。真实部队的区域部署可用带不确定度的区域表示；计算所需的区域内布设必须另标估计，不能标成已核历史阵地。
- 没有定位的部队保留在编制树和待定位清单。AFSIM装载报告必须区分作战实体、指挥节点、地名参照和未具备计算条件的单位；零作战实体不能冒充完整战场初始化。

## 开发顺序与验收

1. 先实现纯标准库档案/快照校验，拒绝无来源、重复身份、循环隶属、无依据数值和错误阶段；对三种用途、两种引擎验证共同初态一致。
2. 优先补齐用户实际遇到的武汉、徐州、冀中档案，并扩展全部45场。逐条记录来源精度，不把参战概述自动提升成完整战斗序列。
3. 接入初态预览、编制树、来源和覆盖状态；联动修正回溯空数组契约和渲染提前返回。旧存档不覆盖、不猜测升级。
4. 将共同初态接入开放DSH/AFSIM过程计算及观测；基于真实单位建立规模合适的武器/人员/后勤模型，校验人工命令、双边决策、状态与账目连续性。
5. 对45场逐场做业务与真实执行验收，再重建安装包。档案覆盖不全、模型缺项或验证缺失时保持未完成，不用启动成功替代业务验收。

当前本规划尚未完成；`docs/历史初态全场景审计-2026-10-27.md`保留原始失败证据。

## 初态接入第一片：版本化回溯与编制视图

- 接入目标：新建回溯局固定来源包与可用的历史番号档案，显示真实单位身份；参战参考不冒充本帧已定位部队。旧v1局保持原契约，不自动迁移。
- 接口：只读`GET /api/historical-initial?battle=...`返回档案状态、版本快照及覆盖缺口；45个目录条目均有明确状态。当前三份档案继续标为部分。
- 状态：新局创建时固定来源包和档案，初始化及推进都从快照读取；取消、模型失败或校验失败不提交。导出恢复不依赖最新档案。来源与档案摘要一并约束帧身份。
- 组件：新增可复用`HistoricalRosterPanel`，在右侧“编制”页显示搜索、红蓝筛选、父级、参战阶段、来源和未知值。未绑定档案的旧局可查询参考，必须明确“未导入本局”。面板隐藏时地图布局保持原状。
- 交互与可及性：搜索、阵营与来源展开使用原生控件；列表纵向滚动，900／1440像素复核，不挤占地图常驻宽度。异步请求区分读取中、未整理、失败和已绑定，切局后丢弃过期响应。
- 上下文：完整定义留在本地快照；DSH默认只接收当前来源事件、覆盖摘要与有限单位页。AFSIM原生观察复用现有DSH插件，不新建工具运行时。回溯参考单位不获得可执行命令能力。
- 验证：TDD检查新局实存番号、双引擎一致、冷恢复、来源更新后继续推进、篡改拒收、有限上下文、AFSIM实体分类；另做真实浏览器和真实原生装载。本片不等于45场开放交战模型已经完成。

## 历史部队参数化执行接入

史实快照保持只读，另建带版本和估计说明的计算输入。计算单位直接绑定历史ID和原番号，不从CA教学底表复制编组。按编制树选择不重叠的作战单位，校验所有可支持的战斗叶节点被覆盖；指挥机关不当作步兵，未绑定的航空／海军不能静默删除。人员、分类装备、部署、库存、性能、时钟、目标均须显式给定，缺载字段标明模型估计，不写回史实字段。

复用既有`missions`账目、命令、目标及封闭原生WSF运算，引入冻结的历史参数化定义，不另建运行时或战斗算法。没有桥梁建模依据时显式禁用桥梁约束，不能沿用教学模板的固定经线阻挡运动或控制目标。DSH默认观察当前数值和参数来源摘要；完整史料档案仍在外部快照中。

先用已登记具名战斗单位做接口、账目、双边火力和目标差异验证；测试参数明确标为QA假设，不能当成完整徐州会战部署或全部45场验收。随后接入DSH配置skill、历史入口与前端，并扩展各战役资料和必要兵种模型。历史开放推演不得继续复用CA代表编组；全目标仍需逐场验证后才能发布。

## 正常历史入口接入片

启动页的历史战局使用独立的具名单位配置组件，合成演习保留原构建器。历史组件先读取档案与各阶段能力，展示真实番号、来源、覆盖缺口；只有具备双方阶段参战依据及受支持兵种的阶段可生成计算参数。缺少档案或绑定时列明缺项，不静默返回教学种子。

复用现有DSH的`scenario-builder`角色、三个原生工具、步骤/预算/取消与轨迹。专用skill读取冻结事实、待填写参数结构及地图地名参照，生成带解释的数值估计；宿主绑定身份，校验所有单位及阶段后按所选引擎做装载验证。禁止模型重写史实快照，不能把城市坐标标成真实阵地。

前端支持阶段选择、自然语言参数需求、来源查看、估计人数/装备/保障编辑和地图选点；编辑或更换引擎使验证失效。名称与ID只读，无增加代表分队操作。草稿固定初态版本；创建时核对草稿、参数、来源摘要与引擎，不重新读取最新档案。旧局维持原样可恢复，新历史入口拒绝CA。异步换战役/阶段丢弃旧响应；生成期间禁改阶段，支持原生取消。900/1440像素检查键盘选择、错误提示、地图部署及实际创建请求；独立真实DSH与AFSIM验收不以响应夹具替代。
