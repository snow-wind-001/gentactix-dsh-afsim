# 分类炮弹计量改造与验收方案

本文接续[会战级改造规划](会战级多层编制与分合兵改造规划-2026-10-31.md)和[火力预算实测](火力资源预算与库存时点复核-2026-11-04.md)。当前是实施方案；完成结论必须以逐项结果和真实执行为准。证据目录：`.cache/qa/classified-fire-accounting-2026-11-04/`。

## 问题与明确假设

旧规则让炮击同时消耗通用弹药工作量和分类炮弹；真实22单位案例因工作量只剩2份而每小时仅射击2周期。该程序行为已核实，历史合理性仍待标定。不能将这种观察直接叫作重复扣弹，也不能调大毁伤系数弥补。

新建配置可显式选择`fire_accounting.version=classified-indirect-1`：**通用工作量代表直射轻武器弹药；炮击、压制按分类炮弹扣账**。这是聚合计量假设，不代表已完成口径、装药、炮班操作能力、运输或历史弹耗标定。火炮、人员、目标、通信、装填、距离、时间和物理炮弹仍约束开火；零炮弹不能取得免费效果。

旧默认火力参照2.3／修订2保持不变。选择新计量的新配置冻结2.4／修订3，旧局不迁移。通用弹药库存和炮弹库存均不自动加减或兑换；运输仍按既有各类实物数量与质量系数对账。

## 实施顺序

1. **先保存旧协议金本并建立失败回归。** 覆盖完整定义、世界、火力参照和生成WSF；复现根`combat_reference`与命令能力读取不一致。
2. **在既有参照模块统一解析。** 配置、冻结参照和按动作工作量成本只保留一个解析点；Native编译、DSH过程账、动作准入及预算共用。新修订不借用旧修订的执行凭证。
3. **贯通既有配置流程。** 历史计算、派生合成、Native分片schema和启动页要求支持新字段；模型遗漏或擅自移除用户选择必须拒绝。复用DSH现有工具，不新增执行器、状态库或模型传输。
4. **保护连续性。** 新v2阶段续接禁止隐式切换计量；旧冻结协议精确重放。配置和操作提示区分直射工作量预算与炮击实弹预算。
5. **真实验证后全量门禁。** 逐项运行Native AFSIM、真实DSH工具和实际前端，再冻结源码运行离线门禁；控制内存并串行执行，不重启旧服务。

## 完成边界

新规则通过只能认证计量合同及已测执行范围。万家岭和武汉的同日编制、武器可用量、长期保障、完整历史效能、原22单位纯DSH主线及270格逐场验收仍需继续。史料缺载人数、武器和弹耗不因本方案变成已知事实；安装版与GitHub另行交付。
