# 前端军事标图来源与专业性审查

审查日期：2026-10-29。只读检查源码、原书转绘目录、浏览器 DOM 和车桥验证局；没有修改标图代码、配置或战局，没有中断在途推演。

## 结论

当前实现是**带部分书籍参考的自定义教学图例**，不是直接使用整套原书军标，也没有足够证据认定符合某版正式军事标图标准。已有可用的图层管理、矢量渲染、DSH 草稿生成和坐标校验，但符号语义、编制表达、动态状态和地图布局仍不完整。

## 来源与真实渲染链

- `data/military-symbols-v2/使用说明.md`注明来源为用户提供的 213 页《军事标图技法》。库内有 256 个独立示例、234 个组合区域、23,544 个自动笔画组及 213 页底稿。24,247 是 SVG 文件数，不能解释为军标种类数。
- 256 个示例经过图形检查，不等于全部语义、年代、定位点均已核验；目录中只有 6 个条目标记了已核验的地理定位点。
- `tools/build_military_symbols.py`手工定义项目绘制的路径，生成`gentactix/military_symbols.json`。当前共 35 个图例：26 点、6 线、3 地域；18 个有关联参考编号，17 个没有。
- Vue 的`militarySymbols.ts → unitMilitaryHtml → tactical.natoHtml → MapView.drawUnits`使用上述小词表。`natoHtml`只是函数名，不能证明采用完整 NATO 标准。
- 原书 SVG 经只读参考接口按需显示在“军事标图”面板，未用于普通部队图标的直接渲染；安装包采用项目重绘词表。

## 逐图对照发现

| 应用图例 | 登记参考 | 核对结果 |
|---|---|---|
| 步兵：框内叉号 | `mil-069`，PDF 第 25 页，表 2.8“长方框” | 原条目明确仅为形状/定位点示例，不能据此赋予步兵语义；关联不足以证明当前画法来自书中步兵定义 |
| 炮兵：框内圆点 | 无 | 项目图例，不能声称已核对书中炮兵标法 |
| 装甲：矩形框内椭圆 | `mil-140`，PDF 第 138 页“坦克” | 原图与应用图形明显不同；装备符号与编组符号也不是同一概念 |
| 防空编组 | `mil-051`，“高炮跟进掩护” | 原图表达特定行动，不能仅凭关联把它作为通用防空单位的标准依据 |
| 指挥所 | `mil-199`，“基本指挥所（空白旗面）” | 旗杆和旗面的基本结构相近；应用有显式旗杆脚锚点，但未表达部队层级/番号组合 |
| 综合补给点 | `mil-001`，“车材油料库” | 应用房屋轮廓与参考图明显不同，含义范围也更宽 |

这不意味着所有自定义图例都不可用；问题是不能把“有参考编号”称为“按书中标准复现”。原书提取目录自身也须继续核对，不能用两个加工产物互相认证。

## 当前车桥局的实际情况

审查对象为本轮运行的 18987 前端及 18986 后端，版本化初态 AJ17-cheqiao/1.2.0，局 ID `459eac0d701a`；不推定其他安装实例已一致更新。

- T+3 快照有 19 个计算实体：红方 12、蓝方 7，其中 5 个待入场。自动分类结果为 18 个步兵、1 个炮兵，无手动图例覆盖、无额外标注。
- 浏览器实际路径与词表一致。多种历史建制和计算分队共用步兵形状，属于表达粒度不足，不能据此判断只有两支部队。
- T+4 浏览器仍有 19 个部队标记，当前缩放下 36×36 像素标记的包围框存在 16 对重叠。代码有邻近单位选择菜单，但没有自动避让或聚合布局。
- 番号开关在源码中默认关闭；本次 T+4 页面已开启，长番号被截断、密集位置标签互相遮挡。默认隐藏和全部常显都不能替代按缩放分级的标签策略。

## 专业性缺口

1. **语义可追溯性不足。** 缺少明确的规则版本、符号释义、适用对象、源页依据及复核状态之间的逐项对应。
2. **编制和身份表达不足。** 图标不组合军/师/旅/团/营等层级；历史单位、下级番号未核单位、计算分队主要依赖完整名称区分。同兵种两方同形，仅用颜色及文字说明阵营。
3. **线和地域显示丢失类型特征。** `mapPlotting.ts`把防御线、分界线、障碍地段绘为通用折线；进攻、撤退、补给路线使用相同箭头；雷场、目标区、集结地域使用通用多边形。图库缩略图的齿形、叉号等没有完整进入地图渲染。
4. **状态表达过粗。** 单位图标主要区分正常、HP≤0失能、待入场和选中。受压制、缺弹、撤退、被俘等没有独立徽标。实际战局已有被俘账，但地图只显示失能，无法从标记理解减员原因。
5. **系统图层尚未统一。** 补给节点仍用`▣`，桥梁用圆点，舟艇另画 SVG；这些未统一使用登记军标及定位规则。射程圈、射界和交战范围是辅助图层，不是部队标记。
6. **地图信息优先级不足。** 卫星底图、补给线、射程圈、长标签同时出现，密集交战区可读性下降；没有根据比例尺、选中单位或任务自动组织标注。

已有基础包括共享词表、未知兵种回退、矢量路径、显式锚点、文字转义、点线面编辑、来源/假设/计划分开保存、跟随单位的标注和旧草稿冲突检查。这些可以继续复用。

## DSH 能力与建议顺序

现有`plugins/dsh-military-plotting/skills/military-plotting/SKILL.md`及原生工具已经支持读取 skill、检索目录、校验草稿；后端限制已知位置和地图选点，确认后保存。当前车桥没有生成额外标注，不能声称该 skill 在每轮自动完成了战场标图。本次没有发起新的模型调用。

建议下一阶段依次处理：

1. 逐项复核常用步兵、炮兵、指挥所、工事、补给、进攻/防御标法，将“形状参考”与“语义已核”分开，保留未核项。
2. 采用“兵种图形＋已知编制层级＋短番号＋状态＋来源属性”的组合渲染；未知层级不猜测，计算分队明确标识。
3. 为不同线/地域实现独立描绘规则，并统一自动补给、桥梁等图层的图例体系。
4. 增加分级标签、重叠展开和选中态详情；通过密集单位、失能/被俘、窄屏及不同缩放的截图回归验证。
5. 扩展既有 DSH skill 的目录释义和适用规则。确定性绘图交给前端；DSH负责选择表达对象与依据，不逐帧生成 SVG，也不修改权威战局。

## 验证边界

`verify_military_plotting.py`本次 14 项通过，覆盖图层隔离、几何、来源访问、过期草稿及工具接口等。它们没有验证整套书籍标图语义，也不能替代标准符合性检查。证据集中于`.cache/qa/military-symbol-audit-2026-10-29/`。原推演链继续完成至 T+4；本审查没有修改业务代码。
