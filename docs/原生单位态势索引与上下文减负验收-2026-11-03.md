# 原生单位态势索引与上下文减负验收

日期：2026-11-03。范围：DSH 原生单位决策的观察输入，不改兵力、部署、装备、库存、历史版本、原存档或模型配置。45 场／270 个完整历史窗口继续未验收。

**当前结论：输入投影、到场信息及只读工具分项通过；正常前端 T4 和整回合性能未通过。** T4 在 24 次效果拒收后耗尽步骤预算，停留原 T3；完整离线回归通过不能替代这个失败结果。

## 修改与边界

原纯 DSH 单位决策将 `commands.view()['units']` 的全军详细名单发送给每个单位智能体；每次还重复发送自己的完整资料和任务说明。AFSIM 路径则只给最初 8 个单位的观察，需要额外分页才知道尾部身份。

新增 `unit-situation-index-1`，两条路径均保留全部登记身份，无固定数量截断、不按名称去重。每条包括当前 ID、阵营、名称、兵种、位置、是否可用、射程、已知现有人数和人员保有率，以及必要的参与状态。未知保持空值；失能但仍在世界中的实体与仅保留身份的退役参考分开，不能把坐标未知当作不存在。

后续发现初版遗漏旧版会战的 `arrival`：没有参与状态模块时，未到场部队仍可能有现员、显示 `available=true`。现已原样保留到场状态、计划时间及其来源／精度信息，并明确 `in_world` 和 `available` 不等于已参战。这项补充先用真实武汉 79 身份夹具的延后到场条件复现，再修复；没有改变原到场判定算法。

自身 `unit` 保留原完整观察、能力、运动与资源约束；人工意图、回合指令和史料规则不变。其他单位的装备、库存、人员账和决策详情通过既有原生 `get_afsim_observation` 按 ID 查询，索引附带 `detail_query`。纯 DSH 路径也能读取该工具提供的当前已提交世界，不要求启动 AFSIM。候选仍经原 `submit_unit_order`、权限校验和整轮原子提交；没有新增世界、缓存、执行器或 SDK 调度器。

这不是战争迷雾、传感器模型或史实实到人数证明；本局计算先验不会因进入索引而成为历史事实。没有手动裁剪、重置或压缩 Native 会话，既有记忆继续由 DSH 管理。

## 回归和真实 SDK

证据目录：`.cache/qa/native-unit-input-index-2026-11-03/`。

先红后绿；最终新增 9 项检查覆盖完整 22 身份、无坐标／未知／失能／退役、79 项同名索引、武汉 79 叶子源身份夹具、自身完整约束、两条后端路径、尾部原生查询和无参与模块的延后到场。武汉数值仍为 QA 估计，不是完整历史部署。初版 72 项相关检查通过；到场补充先红，44 项相关检查通过。初版完整门禁为 157／157 组、1828 项、0 失败／0 跳过、1264.56 秒；**最终 v2 门禁 157／157 组、1829 项、0 失败／0 跳过，分组耗时合计 1289.90 秒**，包含上下文退化及干跑探针。40 份最终源码和 73 份受保护文件核对不变，两轮不重复累加。

独立实际 SDK 测试耗时 98.729 秒，取得两份合法原生命令。公开工具对的独立重放确认：第90师读到尾部佐枝支队；铃木支队读取第60师、第91师及自身，3 份当前观察与正常宿主分派结果一致，单位候选凭证有效，世界和源文件不变。

**该 SDK 测试原脚本失败，不能记为全项通过。** QA 误用了预览／战报专用的 `readonly` 结果过滤条件，普通观察回执没有该字段；独立核验第一次还漏计正常的 `tool` 包装字段，两份失败均保留。另一方面，铃木支队未执行测试附加的“先读最末单位”指令，而是查询相关对手及自身，附加顺序服从仍失败。两个单位还分别出现一次把 `detail` 写成字符串的工具错误，之后自行修正为布尔值。核心数据和候选链路核对通过，不代表模型指令服从、说明全文或整体速度通过；没有重复运行后覆盖原失败。

最终补充版另做一次独立真实 SDK 测试：22.219 秒，44236 字符提示词完整包含武汉 79 个登记身份；一名 Native 单位通过工具读取尾部波田支队，正确识别其 `staging` 状态及计划时间，提交合法待命候选和有出处的公开依据，凭证及数据与正常宿主读取一致。没有改变世界或源文件。这里只验证一名智能体在 79 身份索引下的查询和候选，不是 79 单位物理推演，也不能覆盖前次附加指令失败。

## 正常前端回合与剩余工作

从原 T3 正常创建分支 `1e49e58de775`，保留同一世界、22 单位、9 项持续任务、20 成员与两名 Native 单位智能体配置。按产品既有分支规则使用新 Native 会话，来源会话仍保留在原局；不是克隆来源聊天或修补旧记忆。它运行的是初版索引；该例全部已到场且有参与状态，未重启或重复推进去套用后续补充版。

真实前端 T4 返回 HTTP 502，耗时 2702.027 秒；含终态取证共 2707.514 秒。领域步骤预算耗尽，未提交。两名单位的原生候选凭证有效，但没有取得任何有效完整效果预览，也未到战报提交阶段。世界、人员装备库存、命令、任务、历史、轨迹、组织和回合数与轮初精确相同，新候选绑定未被当作已提交记忆采用。原失败、全部公开工具调用及截图保留。

公开轨迹显示 24 次效果预览全部拒收：前 9 次为粮弹收支、无射击命令却记录交战、无配置工事恢复及疲劳等错误；后 15 次转为结构／字段错误。实际出现 `unit_name/name` 代替 `unit`、更新行夹带禁止提交的 `team`、缺编组及错误命令容器。`'unit'` 和“不得改写单位身份、兵种、来源或性能”的反馈没有指出具体路径和字段，难以帮助模型恢复。原生预览工具目前仅声明 `candidate: object`，没有把这些内部结构固定在工具合同中。结构漂移与压缩的因果关系尚未做对照，不能仅凭时间先后定因。
