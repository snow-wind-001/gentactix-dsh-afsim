# 原生过程预览与战报结算契约

实现状态：Native只读预览、真实工具证据回收及宿主复验已分项验收，见[真实验收与剩余问题](原生过程预览与战报结算验收-2026-11-01.md)。当前摘要为`turn-settlement-2`；机械链路通过不等于通用文字解释通过。

## 要解决的问题

改造前，X18的T+4“粮弹各扣”、T+7“无评分变化”、T+9“无物资消耗”源于两个不同缺口：分类毛收支没有进入完整事实摘要；DSH过程模型在宿主评分前写战报。当时DSH-only过程调用虽使用Native运行时，却未绑定领域工具上下文。本契约补齐该接点，让模型先看到同轮结算；已见错误筛查继续保留。

## 执行顺序

1. 当前Native过程角色通过`preview_turn_effects(candidate)`提交完整候选效果；复用原命令合并、`dsh_simulation.apply`、C2/资源/火力/目标校验，不调用物理执行器、不改世界或命令队列。
2. 工具返回`turn-effects-preview-1`指纹和`turn-settlement-2`有界结算：实际时钟、双方分类粮弹毛收支、人员前后与损失、派生补给指数、目标变化、阶段观察／转换。`condition_sampled=false`时条件为未知；`phase_at_end`另列轮末已激活状态。摘要最多列16单位和64目标并说明未列项，阵营物资汇总仍覆盖全体，不复制整个世界。
3. 同一个DSH原生会话依据工具结果写最终`{preview_hash,report}`。不重复生成整份效果JSON，压缩仍交DSH。
4. 宿主从**本次操作的DSH公开tool/call与tool/result轨迹**取回匹配候选。只接受成功只读预览，指纹同时绑定操作、轮初世界、归一化命令和候选效果。重新校验后比较轮末摘要，再走既有原子提交；没有工具证据、陈旧/伪造指纹、非法输出均拒收。

没有新建Agent运行时、候选缓存或另一份战场账。预览结果只影响模型可见证据，不消耗队列、粮弹或任务次数。现有AFSIM规划路径不开放该工具；未使用Native过程的兼容调用继续原效果JSON路径。旧存档不改写，下一次Native过程调用才采用新握手。

## 权限与展示

- 只给绑定过程上下文的engine角色开放；chat、复盘、AFSIM规划和旧JSON工具循环不得越权调用。
- 工具本身是估计候选校验，不能称实际执行、传感器实测或最终历史战果。持续任务的命令/任务结算仍由原提交链完成，预览不能代称任务已完成。
- 模型依据预览写稿，正文仅在最终提交后发布；不能在已提交的战报中称世界或命令仍待提交。历史／条件句和未来建议与当前事实分别表达。
- 已见分类收支/阶段矛盾仍做针对性筛查；原文留审计。程序摘要补齐分类库存/毛收支和阶段转换，不把净库存变化当消耗。自由文字不称通用语义证明。

## TDD与退出条件

先复现X18三份原文；测试分类零耗用、到货遮蔽净变化、单位/阵营范围、未知回执、历史/条件句以及阶段起止。预览握手另测：不改输入、非法候选、固定/人工命令、跨世界/操作/回合、失败工具、伪造/缺失轨迹、取消与冷恢复；没有预览证据不能退回未核的JSON或重复执行。

通过相关回归后执行根目录全门禁和上下文退化；实际DSH必须留下原生工具调用与成功回执，人工核读结算后正文。正常HTTP及浏览器验证战报、资源、目标和阶段一致，失败/刷新不重复推进。实际模型重试、原文失败、规模和能力边界分开登记；不以一个试点关闭完整45场准入、实体生命周期或历史标定。
