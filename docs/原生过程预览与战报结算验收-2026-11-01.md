# 原生过程预览与战报结算验收

日期：2026-11-01。对应[主规划](会战级多层编制与分合兵改造规划-2026-10-31.md)Q01及[预览契约](原生过程预览与战报结算契约-2026-11-01.md)。本报告验收过程候选、结算、取消和恢复链路，不是完整万家岭或45场历史效能证明。

## 1. 结果与边界

Native过程角色已实际完成“生成效果候选→调用只读预览→读取同轮结算→返回预览引用及战报→宿主复验并提交”。正常前端完成12轮、10个QA阶段和90分钟间隙；另有双向交火、原生取消重试、5局冷恢复证据。**机械链路分项通过，通用文字解释、完整会战与历史标定仍未通过。**

输入使用万家岭1.2.0的六个历史身份；各300人、近距离部署、资源和十阶段均是显式QA估计，不是史实实力或历史阶段。四个单位待命、两个互射的对照只用于检查命令、过程与账目。没有自动晋升默认史料、改写旧局或替换安装程序。

## 2. 实现与DSH职责

| 接点 | 本轮变化 |
|---|---|
| `backend/dsh_simulation.py` | Native过程提示绑定预览语义；最终采用`preview_hash/report`，从当前操作公开轨迹回收效果并复验 |
| `backend/turn_preview.py` | 沿用原`apply`只读计算，绑定操作、前态、命令、效果、期末和结算；解释未知采样与轮末激活 |
| `backend/harness_engine.py` | 仅非外部Native过程角色移除不适配效果候选的旧`evaluate_action`；其他角色／AFSIM路径保留 |
| `gentactix/turn_settlement.py` | `turn-settlement-2`记录粮弹毛收支、五类物资耗用、人员前后账、派生补给指数、目标采样与轮末所属阶段 |
| `gentactix/reporting.py` | 区分预览写作和提交后发布；修复实际出现的粮弹、仓库作用域、满编否定、目标前后状态及阶段误报 |
| `verify_turn_settlement.py` | 28项正负例；缺失／伪造／失败／跨操作预览、取消、人工优先和已见文字错误均有覆盖 |

仍使用DSH Native插件、角色、事件、取消及compact；没有新增Agent运行时、候选缓存或另一份世界账。预览不执行AFSIM、不消费命令和持续任务。最终效果仍经宿主原事务链提交。

预览的`after_hash`绑定领域`apply`结果。Main随后可能补充`carried_forward:false`等名册元数据及空损失归档，故完整世界原始哈希不保证等同；已检查领域结算哈希一致，最终检查点另留摘要，不能用忽略实际账目差异的方式“配平”。

## 3. 从实际失败形成的TDD

- 原T4“粮弹各扣”、T7“没有评分变化”、T9“无物资消耗”保留原文只读重放。T9曾因同句提到仓库而漏检，修为按实际主语约束，不能免检全句。
- 新真实首轮“本轮不据此称满编”曾被误杀；补否定句正例及后续再肯定的负例。
- 新战报称补给指数不变，但实际库存派生指数下降；改用共享`index_value`前后值，不读陈旧的原始指数。
- “由未达成转为完成”曾被当成当前未达成而误杀；现在分别核对轮初和轮末，错误轮初仍拒绝。
- 目标尚未采样不等于条件为假；轮末阶段已激活也不等于目标本轮已评分。新增`condition_sampled`与`phase_at_end`，不把二者合并。
- 战报在提交后才显示，“命令仍待原子提交”会误导操作者；增加发布语义与已见冲突检查。

完整红灯、转绿及原模型响应保留在`.cache/qa/turn-settlement-2026-11-01/`。没有为了转绿降低思考强度、放宽整数守恒或重写旧失败历史。

## 5. 人工审核仍发现的问题

自动`screened`只表示已知规则未命中，不代表全文正确。最终持久角色首轮仍出现：

1. 先正确说明阶段2尚未采样，随后却把“其余兵力保持方向”概括成未满足条件。未来阶段应保持未知。
2. “粮耗取轮初库存与到货的较小值”错误；实际应受需求和可用库存约束。本例实际扣粮数字2正确，算法解释仍错误。

较早12轮还发现一次距离约560米的非提供推算（实际约485—488米），以及T12集合被概括为完整师、已被现有规则截为程序摘要。双向交火第二轮账目与时序一致，但存在“受估计均升至24”等缺少指标名称的文字，不宜作为教学定稿。

这些记录为X20及X18未关闭部分。下一步应让结算事实、引用和自由解释有明确契约，人工审核命令、库存、人员、阶段及算法措辞；不能靠继续堆词表宣称通用事实核验完成。地图上六实体部署很近时仍有重叠，名单可独立选择不代表百单位地图交互已验收。
