# 同世界跨阶段与撤销返场验收

本次继续 K04 的途中／跨阶段组合验证：已有伤损的同一单位在阶段切换时撤出、撤销、场外等待，冷恢复后实际返场并继续原任务。数据来自万家岭1.2.0的六个来源身份，但兵额、部署、道路、阶段时长与资源均为软件QA估计，不是完整历史过程或效能标定。45场／270个完整历史窗口不因此通过。

## 当前架构的阶段边界

`campaign_lifecycle` 在同一世界调度目标的生效阶段，不复制单位、重置任务、补员或重建库存。旧 `phase_continuity` 分支则明确拒绝带持续目标图的阶段续接，防止目标进度被清空；本次没有移除该约束。人员集合改变、渡运设施变化、编制替换或历史版本切换，仍须各自的分配与交接契约。

“撤销单位命令”和“下达待命”也有不同含义：前者使用既有 `DELETE /commands/{id}`，临时撤出可以中止，原任务仍按权限与窗口保留；后者属于人工接管，旧任务不会自动抢回该单位。不能为了让测试通过而改变人工命令优先规则。

## 测试中保留的失败及架构含义

旧辅助模块导入曾把QA请求端口从19140切回19136，导致404；测试在原提交T2明确续跑，未重复前两轮。另一次错误使用待命接管、一次错用撤销URL，以及取消蓝方一次性射击后未继续下达蓝方待命，都保留为QA失败。正确流程另建隔离局 `controlled/`，没有抹掉旧局或把不一致前态修成预期结果。

未覆盖的可行动单位会交给DSH自主规划。前两次QA中 `model_skipped=false` 不表示AFSIM没有执行物理过程，而是实际额外调用了模型规划；给双方完整明确命令后，正确原生链路无规划调用。因此不能把“使用AFSIM”一概理解为“没有LLM等待”。并行初始化还因已有操作而被409拒收，依照当前串行模型顺序执行；本次不承诺并行多局计算能力。
