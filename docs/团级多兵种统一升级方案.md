# 团级多兵种统一升级与验收

## 本轮要求与边界

补齐步兵/装甲、炮兵、防空、航空、工兵设施、后勤指挥六类可计算教学模型。AFSIM是后台计算与运动平台，DSH通过已有原生插件控制与按需观察，继续使用当前地图、命令面板与分析台。模型数值属于版本化教学假设，不将合成编制写成历史真实部署。

45个战役各提供统一模型初态；根据时代禁用不适用的装备。保留史料和旧定义以支持备份导入。默认新建AFSIM局采用统一模型，旧对局只有在综合想定及目录验收通过后才备份、清理，模型密钥与配置不改。

## 实现合同

- `gentactix/combined_arms.py`：纯输入定义、时代能力、参数版本、动作和守恒校验；没有Python战斗执行器。
- `backend/afsim_combined.py`：封闭WSF模板。分类装备可用/待修/毁伤、疲劳/压制/工事/防护/展开、炮弹/冷却、防空弹药、施工/通行、运力/油料/备件、通信延迟与情报老化由真实AFSIM计算并回传。
- 不逐人或逐发建实体；编组是聚合平台。既有WSF mover、原生调度器、回调、DSH MCP及检查点继续复用。
- 工事、地形与武器系数未作实战标定；桥梁是局部教学设施。当前指挥情报时效影响射击效能，地图仍是全知教学视图；不宣称雷达或真实战争迷雾。
- 每回合1800秒；通信等待和疲劳缩短有效行军时间。桥梁开放、走廊及共享通行容量可以阻止移动；保留AFSIM实际坐标，不强行拉回命令落点。持续移动沿用现有命令系统。
- 弹药工作量、炮弹/防空弹药发数、航空油弹工作单位、地面油料升、备件/材料包和补给吨数分开标注；教学补给包总质量为0.25吨，不将包内粮弹重复计重。

## 前端改动简报

沿用LaunchScreen的战役选择和想定下拉，新增“统一团级多兵种”条目并在AFSIM模式默认选择；明确合成初态与史料差别。CommandCenter增加炮击、压制、构筑、架桥、破坏桥梁、装备维修、侦察和恢复联络；炮击/压制复用敌方目标和地图选目标。

在已有分析台加入“兵种与保障”页签：展示各单位分类装备账、库存、疲劳/压制、通信等待与情报年龄、当轮炮击/防空弹耗、维修和运输；展示桥梁施工、完整度与共享通行容量。在现有地图叠加教学桥梁和炮兵/防空范围，不创建新地图或新Agent运行时。所有结果注明AFSIM教学计算与参数版本。

## 验收顺序

1. 先失败回归，再实现；检查时代能力、动作约束、模型版本、人员装备守恒。
2. 真实引擎对照：保护/展开/疲劳/压制改变火力；炮弹和冷却约束炮击；防空无弹与有弹产生差异；缺桥、容量不足阻止越河；无运输/断油阻止到货；维修消耗备件；联络与情报老化影响行动。
3. 45条目统一模型真实装载、推进、存档与恢复；旧版回归保持通过。
4. 浏览器宽窄布局、地图选点、新动作、结果和DSH观察；进行一局真实DSH完整推演到程序目标结算。
5. 条件满足后，将用户旧对局备份到项目目录，记录清单，再清空旧存档；保留本轮新对局。随后打开当前前端供用户继续使用。
