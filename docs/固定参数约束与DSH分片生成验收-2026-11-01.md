# 固定参数约束与DSH分片生成验收

日期：2026-11-01，未发布源码。对应X29及K00／K03分项，完整会战目标不缩减。

## 原因和修复

上一轮真实生成与自然语言附带的QA输入有20处数值差异。原生成器只硬约束启动页时间、范围、模式等条件；自然语言数字不能证明模型已保持该值。事后把错误输出改回去也不能当作模型遵从。

新增“生成前指定数值”表单：选择公共参数或历史单位，再选择项目、填写数值并固定。可指定当前模板的人员、分类装备、位置、目标、保障和规则等数值；选中的保障模型会提供相应字段。中文对象和项目标签代替手写JSON／坐标路径。更换史料版本或阶段会清空固定表；停用依赖模型时保留并提示冲突，不能静默丢弃固定值。

`gentactix/scenario_constraints.py`仅负责数值输入目录、绑定和校验，不执行战局。现有生成接口新增`fixed_parameters`，宿主在模型调用**之前**把用户数值及契约放入候选模板。DSH沿原有Native AgentRegistry、分片草稿、版本号和`get_scenario_basis`／`update_scenario_configuration`工作，不新增运行时、调度器或状态载体。

模型写入违反固定值时，更新整体失败，返回`fixed_parameter_conflicts`，不改变草稿或revision。公共片只读公共约束，单位片再读本片单位约束；最终验证和宿主装载再次核对。预填固定值不等于模型已提交更新。完整字段目录只供前端使用，不复制到每个模型上下文。

## 手工修改与证据

- 固定值参与前端验证签名。下方编辑值与固定值不同时显示提示；“应用此固定值”是明确的用户编辑操作。
- 重验省略固定表时继承父草稿契约；显式提交空表表示解除，提交新表表示替换。不能用参数编辑绕过尚未解除的固定值。
- 新手工草稿记录`manual_revision`和父ID，保留原草稿；解除后不能在当前元数据中继续声称该值仍被固定。
- 实际装载失败保留的配置及重试继续携带同一契约；旧草稿无此字段时保留原流程。

v1只支持模板已有的**数值映射叶子**，不锁定文本、开关、列表结构或历史身份。有限数／整数和路径检查不代替完整领域验证：相互矛盾的预算、历史事实或部署仍须拒收。指定数值是模型输入，不自动升级为已考证兵额或实测位置。

固定项只约束初态生成及重验，不冻结战斗中的现有人员、库存或位置；推演后的减员、消耗和运动继续由当前世界与实际回执核账。

数值类型按领域含义判断，不依据初值恰好写成整数就禁止小数。人员、装备和绝对库存计数仍为整数；坐标、距离、时率和换算系数允许合法小数。输入端把整数值6000.0规范为6000，不改写模型输出。全目录实测最多2152个数值字段，接口上限调整为8192；该上限不代表已完成8192单位或全字段浏览器压力测试。

## 目录复核及本轮新增缺口

只读复核45场、56版本、292个阶段／范围组合，209项可配置、83项明确未准入；最大目录2152字段。44场在所有版本中至少有一个可配置入口，但按**默认版本与默认阶段**直接进入仅43／45可配置。这是配置目录结果，不是历史过程通过率。

- **X30／P0入口准入**：冀中默认及其他阶段均因航空参考`ww2.jp.flight29`的阶段参战未核而阻断；武汉默认1.0开局会把累计名单误作同时到场，被现有保护拒收。武汉1.1另有可选会战范围，但不能据此擅改默认或把累计79单位宣称同日部署。下一步核来源、阶段参与和范围选择；保留冻结版本，不靠删除保护换取启动成功。证据`default-entry-review.json`和`catalogue/result.json`。
- **X31／P1标图可读性**：22个DOM军标在当前视野形成8个连通分组（含单独标记）、25对边界相交。单位没有因此丢失，但不能声称均能直接点选。现有邻近编组弹窗已实际点击，三项候选中选择第161师万家岭投入部，正确进入指挥面板且未下令；这不证明全部22单位的点选可达性。显示层仍需更清楚的聚合数量与展开反馈，保持真实单位ID和物理坐标；不以挪动战场坐标解决显示重叠。证据`map-overlap-review.json`。

另一次全新AFSIM执行连续20轮、每轮6小时、22单位、3080事件完成；无失败／恢复。该测试为路线遮断关闭的待命资源核账，模拟120小时，不是运行120小时、完整历史交战或X24所有环境故障已排除。原早退失败继续保留。证据`.cache/qa/supply-schedule-2026-11-01/extended/1793533506636689961/result.json`。
