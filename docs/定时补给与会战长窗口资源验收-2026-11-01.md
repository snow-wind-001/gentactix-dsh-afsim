# 定时补给与会战长窗口资源验收

日期：2026-11-01；未发布源码。对应主规划K07／K09的有限分项，完整会战目标继续执行。

## 问题与实现

原模型的普通补给／主动补给分别受每回合2／8工作量限制，耗粮却可按小时计算。相同六小时拆成不同回合，会改变补给机会；只把轮末到货上限乘小时，也无法解决本轮前段饥饿、后段物资不能使用的问题。

新增**可选**`scheduled-supply-1`，不改变旧局、默认历史初态或未启用它的规则：

- 固定到货周期、普通／主动服务工作量时率、车辆周转速度、装卸时间和逐仓装卸吨位，连同估计依据冻结在本局定义。
- 到货前先核算该段耗粮、缺粮债和非战斗失能；到货后才能支付后续消耗。轮末单独结算，没有额外配送奖励。
- 同仓部队共享每个服务周期的装卸额度，粮、弹及分类货物计入统一货重；保留原有具名仓库绑定及逐仓粮弹扣库。其他分类货物仍是阵营池。
- 车辆可用量、人员比例、往返距离、车速、装卸时间约束聚合运输能力。此模型假设服务管线已运行，**没有具名车队在途、货批到达或运输燃油账**。
- 日期型时钟以本地民用日期锚定周期，相邻阶段分支重置局部累计时钟时仍保持到货节拍；相对时钟按累计秒数。这里不推定历史时区或实际运输时刻。
- AFSIM执行原生分段过程；Python只编译、解析及验证。DSH关闭AFSIM时通过原Native预览／报告工具提出同契约候选，宿主核账后提交，没有第二套世界状态、模型调度器或上下文压缩器。

v1要求同时启用`time-sustainment-1`和分类粮弹，关闭尚未接入此时序模型的共享跨河设施。每轮最多96次到货，配置过密时明确拒绝。仓库分配沿原生单位执行顺序，不宣称公平分配或最优调度。参数均为显式估计，不能升级为史实。

## 前端与观察

历史单位配置页可要求生成定时补给，和舟艇要求互斥；编辑周期、时率、周转、逐仓容量与依据后须重新验证。缺少依赖或必需模型时不能初始化；主按钮仍可发起“生成／验证配置并进入”，不等于绕过校验。

普通Native观察只返回事件数、到货时刻及合计，完整事件经已有`detail_query`读取。旧回执不重复塞入模型输入。粮秣编辑器按当前配置显示分段或轮末口径。

## 实际发现、修复与未通过项

1. **库存浮点越界**：第12小时出现弹药`100+约3.2e-11`，原生结果被严格拒收。修复在AFSIM库存输出边界，未在宿主偷偷改候选；从保留第6小时继续到120小时。旧失败和后续QA末尾元数据变量遮蔽错误均保留，最终独立只读复核完整20轮链。
2. **初始化探针不兼容**：首轮真实生成返回502，实际是0.001秒装载校验不支持新事件规则，不能误诊为vLLM断线。探针现在只结算并保留小数时间，实际重试成功。
3. **相邻阶段周期重置**：先有失败回归，再改日期锚定及冻结配置一致性；禁止阶段定义静默删除时序模型。
4. **模型未忠实保持数值指令**：真实生成与自然语言附带的QA参数有20个数值差异，其中补给时率被改为1／2、仓库容量改为2。`requested-versus-generated.json`逐项留证。编辑器直接输入和重验保留1800秒及4／16等明确字段；目前不能宣称自然语言数值约束已被结构化锁定。
5. **解释仍待核**：生成的自由说明残留“轮末”表述，尽管运行规则及编辑器已按定时配置执行；X20模型解释验收继续开放。DSH独立过程也有两次错误预览，成功恢复不等于首次候选必定正确。

最终编辑器浏览器检查另存`editor-final-review-*.log`：复用保留的真实生成响应，仅作最终界面回归，实际校验仍请求当前AFSIM；不计作第二次真实模型生成。QA曾误将可触发校验的主按钮当成必须禁用，及将分支回执的局部轮号当物理账不一致；修正检查方式，不改业务规则或抹去失败记录。浏览器JSON还会丢失整数／浮点字面形式，定义摘要复核取原始持久化检查点并与界面数值独立对照。
