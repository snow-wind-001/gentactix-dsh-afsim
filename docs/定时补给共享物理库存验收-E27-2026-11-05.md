# 定时补给共享物理库存验收

2026-11-05，运行时源码 `8b772cdb1e91ce3a`。本轮推进 R02 的定时保障整合，45 场×3 用途×2 后端的 270 格验收范围保持。

## 修正内容

原定时配送器维护自己的粮食和缺粮账，连续机动组件则维护实际移动、粮食、疲劳及微升燃油；直接拼接会产生两套库存。本轮复用已有配送分配器，在到货时先结算当前物理时段，再向同一份 `cn_food`、`cm_fuel` 入库。共享仓库装卸、运输容量、分类物资扣库及路线控制仍由原有 Native 逻辑执行；Python 只编译、核验和提交，不分配货物或代算物理过程。

新增 `gentactix/sustainment_intervals.py`，统一原生营养回执与后续模型声明的只读核验。缺粮债、失能、携行余量和实际 `moving_ms` 连续，未来到货不能抵扣此前缺粮；到货必须形成时段边界。同秒到货后仍有末态结算，但不产生第二次配送或额外经过时间。

`scheduled-supply-1` 配置及旧执行默认行为保持；连续机动配置派生 `scheduled-supply-2` 回执。新回执通过 `fuel_timeline` 逐时点记录整数微升，分类 `spent` 禁止以整升桶差代替实际耗油。每次微升到货必须与同次分类整升入库一致。
