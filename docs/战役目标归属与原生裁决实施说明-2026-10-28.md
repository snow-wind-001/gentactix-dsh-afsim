# 战役目标归属与原生裁决

## 问题与实现范围

当前局部模型的目标方固定为红方，蓝方进攻、突围无法作为主目标进行判定。本次扩展已有历史参数、原生WSF裁决和DSH观察，支持红/蓝方的地域夺控、迟滞与突围目标；旧局未指定时仍按红方处理。原有历史事实、部队、伤亡和资源算法保持原契约。

源档案只证明阶段与任务。马良山10月5日推荐蓝方突破前沿第一线，不把10月6日主峰巩固提前；上甘岭仅判地表目标，不把地表占领等同坑道体系消灭。每个推荐保留来源与缺项，不以通用胜负替代完整历史过程。

## 数据与状态

- `goal.team`是新增可选字段，仅接收`red/blue`。新模板明确填写，冻结定义保存`objective_team`；旧参数未含该字段时，不补写旧定义或改变摘要。
- 目标方的单位数用于存续门槛和提前失败；地域控制仍要求有本方、无对方且压制未超过现有阈值。胜方与目标方区分，失败时由对方获胜。
- AFSIM负责原生目标条件、连续回合和截止判断；DSH关闭AFSIM时沿用现有程序目标核对。不新增战斗执行器或智能体运行框架。
- 同源合成派生继承目标方，改编部队后按该方人数检查门槛。DSH通过既有观察工具读取目标方、指标、状态和胜方。

## 前端改动

沿用`HistoricalScenarioComposer`：在已生成配置中增加目标方、支持的目标类型、截止回合、连续回合、范围及存续门槛。页面展示所选阶段的来源建议及模型缺项。编辑只修改草稿，立即使旧验证失效，重新校验后才允许创建。目标方选择有明确标签，窄屏沿现有表单换行；不引入依赖或改动地图工作台布局。

## 验证顺序

先写失败回归，覆盖蓝方成功/失败、双方争夺、连续控制中断、目标方全灭、对方全灭但目标未占、存续上限、旧局恢复、合成继承及观察内容。再运行真实AFSIM目标对照与决策差异，完成DSH生成/规划/观察和前端编辑失效检查，最后运行全量回归、类型与生产构建。所有真实测试使用独立QA服务和显式数值假设，保留原存档及配置；本次不发布安装包或同步GitHub。

## 源码与回归结果

新增`verify_objective_team.py`的19项回归已通过。先保留不支持蓝方、生成省略目标方、DSH独立提示缺少归属及进度的失败记录，再修复；不是只测模型会输出红蓝字样。原有新建流程的测试夹具现在明确填写目标方，旧冻结参数夹具仍不补写，用于验证兼容。

`get_scenario_basis`沿用当前原生工具，新增9个局部阶段的任务建议、来源和未覆盖机制。白虎团任务目前只作地理代理目标，未实现指挥中断或潜入的完整判定；上甘岭仅指地表控制。不同类型不能因为同属“进攻”就宣称已有相同历史过程。蓝方交通破袭、地下存续、受降规则尚未实现，配置直接拒绝，未静默换成红方。

前端已生成的目标方、类型、截止、连续轮数、存续门槛和目标点可编辑。改动使原验证失效，需实际重新装载；不适用字段禁用。目标归属不等于用户控制方。查看截图发现帮助文字直接显示`required_turns`，已改为显示实际数值和中文字段名。长篇建模假设曾挤占目标与进度，浏览器先复现失败后改为默认折叠，资料仍可展开；类型与生产构建再次通过。

## 真实原生与双引擎验证

原生组件检查使用有来源的马良山双方ID，但人数、坐标、装备与数值门槛是显式QA假设。9个案例完成22次AFSIM执行：

| 决策或条件 | 原生结果 |
| --- | --- |
| 蓝方进入目标并连续控制 | 蓝方胜 |
| 相同初态，蓝方不移动 | 到期由红方获胜 |
| 双方均在目标内 | 不计夺控 |
| 蓝方离开再返回 | 连续轮数重置后重新累计 |
| 蓝方突围或迟滞 | 按蓝方人员与出口条件判定 |
| 红方抵达蓝方迟滞出口 | 蓝方未达标 |
| 蓝方被实际火力消灭 | 蓝方提前失败 |
| 红方全灭但蓝方仍在目标外 | 保持未完成，进入目标后才累计 |

正常前端完成DSH真实skill读取、来源核对、参数生成、AFSIM装载与创建。第一轮真实DSH读取态势和史料后下达双方移动命令；红方撤离、蓝方进入目标，04:00→04:30，进度1。前端“蓝方全部待命”只读对照保持红方撤离，进度变0，主局不变。第二轮全人工待命跳过模型规划，AFSIM在05:00判蓝方连续控制2轮获胜，额外推进被拒绝。

相同完整参数通过关闭AFSIM的验证后创建另一局，来源事实逐项相同。两次真实DSH估计执行移动/待命，程序按实际候选位置累计蓝方进度1→2，05:00结束。其效果明确标为`dsh_model_estimate`，没有伪称AFSIM回执。这些未交火案例零减员合理，也证明目标计算不依赖伤亡配额。

DSH独立案例两轮保留了80粮食余额，AFSIM同源案例实际为80→76→74。因此这次只通过了DSH目标归属、位置和守恒验证，未通过“独立模型的行动粮耗与原生规则一致”验收；不能把未发生净消耗解释为保障充足，也不据此宣称全后勤功能通过。

真实DSH只读复盘实际调用观察、完整聚合变化、明细和历史检索工具，正确解释蓝方目标、进度、胜方及局部范围。自由文字仍将每单位两轮总粮耗6误称“每轮2”；实际第一轮4、第二轮2。程序账未改，保留该错误，不把模型整段文字计作通过，也未反复重问以挑选正确答案。
