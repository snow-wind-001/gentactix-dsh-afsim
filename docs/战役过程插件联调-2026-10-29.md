# 战役过程插件联调（未发布）

本轮接通完整战役过程所需的数据、控制、观测与配置接口。**过程机制已获得真实执行证据，完整车桥战役仍未通过历史验收。** 原来的四单位、四小时测试局没有被扩充或改写成整场战役。

## 本轮实现

- 来源阶段声明 `combined_operation` 后，必须配置各历史单位入场时点、永久工事、受降条件和多个阻援区域。分批援军可引用既有互斥计算分队，各批共享父单位兵力账。
- AFSIM 的既有 WSF 编译和遥测通道负责入场、工事消耗与被俘效果。DSH 独立模式提交自己的过程估计，程序校验到场、数量、来源与命令关系，不调用 Python 战斗执行器或补造结果。
- 战役目标在截止回合同时检查据点、所有阻援区域和人员保存；占据一个点不会提前结束。目标说明由程序参数生成，避免仍显示旧的局部迟滞文本。
- 既有 `get_afsim_observation` 返回每个单位的等待/入场状态、工事完整度、当轮被俘和联合目标。没有新增第二套智能体运行时。
- Vue 配置页增加入场、工事、受降及阻援区域编辑，沿用地图点选入口。指挥面板复用目标选择处理受降。地图区分等待部队，并对没有部署的史料回溯显示明确说明；地名圈不会被计作部队。

AFSIM与DSH过程检查使用明确标注的三单位软件QA配置，不能称作车桥真实编成。组件检查验证参数编辑与地图选择事件，尚未证明完整车桥想定从普通启动页生成、编辑、运行的全流程。地图截图也不构成卫星瓦片加载或历史地形配准验收。

首次独立观测脚本漏注册生产工具分发器，工具实际返回HTTP400；最初仅检查调用存在的通过标记已撤销，原回答保留。修正脚本后同时检查工具返回 `ok=true`、实际单位数和公开回答。浏览器脚本的启动页切换、临时组件运行环境也经历修正，失败记录均保留。保留检查曾使用不同JSON空白格式造成摘要不匹配，改用基线相同的规范编码后72份全部一致。

证据位于 `.cache/qa/cheqiao-complete/`：`offline-results.json`、`native-latest.json`、`model-latest.json`、`review-latest.json`、`browser-result.json`、`preservation-result.json`，以及它们指向的原生脚本、世界、工具回执和截图。
