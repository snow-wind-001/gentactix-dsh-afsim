## 问题与修复

之前每单位每回合通常只执行一次火力，15分钟、30分钟和数小时的效果接近；炮兵装填按“整轮”而不是秒数处理，小数毁伤又被逐次取整。这会系统性低估持续交战的累积损失。

现在由现有DSH原生AFSIM插件执行封闭WSF脚本：通信命令到达后，在有效射程、人员可用、弹药足够的条件下重复射击；分别累计实际周期、炮弹发射量、弹药工作量、有效火力时长及停止原因。毁伤小数跨回合保存，最终人员与分类装备账仍须守恒。没有新增Python战斗执行器。

初次真实复测发现两个后续缺陷，均保留失败证据后修复：

- 压制和情报只在回合末改变，导致一小时与两轮半小时的伤亡相差约46%；改为随原生时间连续更新。当前默认模型为`aggregate-fire-cycles-2.2`，旧快照保留自己的参数版本。
- 装备损伤按绝对火力压力扣件，少量人员伤亡就可能使炮兵装备全失效；改为按实际可用装备、人员损失比例和分类易损系数累计损伤，保留小数。

## 历史参照与计算假设

`gentactix/combat_effects.py`连接既有史料库。45个目录条目均有参照入口：35个读取结构化资料，10个保留史料卡原段落。每个数字保留阵营、指标、时间/地域范围、争议和来源；“减员”“死伤”“阵亡”“毙伤俘”不混用，缺载值不填0。这些入口的覆盖不代表45场已完成战损标定。

可核对的局部参照是新华社2018年报道的第31师：原8000余人、死伤近3000人；该报道没有给出这项分师统计的准确小时窗口，因此不能据此倒推出逐小时必达阵亡人数。[人民网转载原文](https://cpc.people.com.cn/BIG5/n1/2018/1219/c421684-30476925.html)

台儿庄炮弹消耗叙述提供了战场每日弹耗的量级参考，不能套给每个单位；来源也没有提供统一的单发杀伤率。[盐田区档案馆资料](https://www.yantian.gov.cn/ytdayszxxw/lsjt/content/post_11737199.html)

FM 8-55第3-10节用于支持按接敌比例、兵力层级、火力、地形和作战强度考虑损失，未提供本项目的120秒聚合周期、0.25阵亡比例或装备易损系数；这些均明确标为可审阅的建模先验。[美国陆军原文镜像](https://www.globalsecurity.org/military/library/policy/army/fm/8-55/fm8-55.pdf)

新建或升级计算局保存本局参照快照，反事实须核对运动版本、火力版本与参照哈希。模型只收到有界摘要和来源指针，完整态势、统计及账目留在工程内。DSH-only收到同样参照，但过程结果明确属于模型估计。历史回溯的来源帧不被火力规则重写；开放推演不强制匹配历史总战果。

## 人员、装备与界面

新增人员分类为`killed/wounded/missing/captured/unclassified_casualties`，合计必须等于战斗减员；非战斗减员单列。旧损失没有分项时保持未分类，不能追认为阵亡。当前原生新增伤亡按显式比例拆分死伤，尚无新增失踪/被俘的生成机制。

右侧“保障”展示人数、损失率、死伤分类、分类装备、实际火力周期、弹耗、冷却秒数、停止原因及历史参照链接。战报区分本轮减员与累计死伤。DSH独立推演的射击坐标、武器类别和射程在候选提交前校验，错误进入现有一次反馈重试，不放宽几何规则。

## 实际验收范围

真实AFSIM采用三个有出处的部队ID，但人数、坐标和装备是显式QA假设，不能视为已考证的台儿庄完整部署。双方持续炮击，另一个单位待命，六轮30分钟共3小时：

| 单位 | 投入人数 | 战斗减员 | 阵亡估计 | 负伤估计 |
| --- | ---: | ---: | ---: | ---: |
| 第31师 | 6000 | 128 | 32 | 96 |
| 日军濑谷支队 | 3000 | 38 | 9 | 29 |
| 日军坂本支队（待命） | 1800 | 0 | 0 | 0 |

这些数值证明持续结算、分类与守恒链路，不证明历史交换比正确。加强掩护会减少伤亡，停止射击不会为了匹配历史而自动死人；只有5发炮弹时只发射5发，工作量不足时也会停止。最后一轮双方各14个火力周期，分别消耗224/336发炮弹。

同初态一小时整轮的双方减员为102/24，两轮半小时为101/23；剩余差异包括再次下令的通信等待和离散装备更新。不能要求有通信与命令差别的两条执行轨迹严格相等。

离线全量49/49组、502项unittest、0跳过，前端类型与生产构建通过。新增10项战损回归，真实原生时长/火力/资源检查13项。可复验命令（真实项必须使用独立QA服务；旧QA导出导入项还依赖18993的前一轮QA实例）：

```bash
python verify_combat_effects.py
python verify_all.py
PYTHONPATH=. python tools/qa/combat_effects_live.py --live --port 18994
PYTHONPATH=. python tools/qa/combat_effects_agents.py --live --port 18994
```

真实DSH另完成双方指挥后由AFSIM执行、关闭AFSIM独立推演及旧版QA导出导入续算，共16项检查通过。实际问答通过原生工具读取当前账，复述128/32/96与38/9/29，主战局未改变。自由文本解释仍有把“死伤”扩大为包含失踪的表述，需要核对来源；数值守恒和工具调用通过不等于史学解释全部正确。

1440与900像素真实浏览器共23项检查通过，无接口替身；可读取实际分类计数、火力周期与来源，关闭参考后可见人员账，无页面横向溢出或脚本错误。六份用户存档、模型密文及密钥的原摘要均未改变。

离线、真实原生、真实模型及浏览器证据位于`.cache/qa/combat-effects/`。45场完整历史初态、逐阶段接敌条件、兵器效能与装备损失统计仍待补齐，历史业务验收继续保持0/45。此次修改没有把参考资料覆盖率当作有效历史推演通过率。
