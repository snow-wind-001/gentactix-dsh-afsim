## 当前需要解决的具体问题

1. `historical_operations.partition`筛选阶段实际在场叶子，`campaign_scope`筛选累计候选。两者解决不同问题；把累计列表直接当同日部署会提前投入援军，把一个局部阶段冒充会战又会缩成少量单位。
2. 默认`campaign.objective`主要是据点控制、阻援区域和兵力保存；可选新图已有多方向评分依赖和同世界持续任务状态机。多个军的真实通信/收令、支援资源占用和完整历史任务仍须补齐。
3. `phase_continuity`仍有相接时钟、相同配置、最多8次等限制，不能代替有空档、撤出重入、改编的持续会战。
4. 万家岭补核资料可支持6—10日若干动作与钟点，但不足以证明每天全部师的精确部署、人数、库存和日方联队序列。不能先造完整部署，再用叙述为其背书。

## 1. 版本、实体和状态约束

- 新增可选、显式版本化的持续会战定义；未选择的旧局继续原算法，旧冻结初态和目标绑定不改。
- 会战持有唯一执行叶子登记与账本。阶段是任务/约束的变化，不能重新复制一份满编人员、库存和位置。
- 身份至少区分历史实体、部分投入身份、计算分队、当前命令引用。历史“欠一团”不能自动生成两个未知番号的团，也不能等同全师。
- 行政关系、开局作战指挥、运行临时主指挥、支援分别保存。组织调整本身净资源变化为0；任务图只读物理结果，不按历史配额改战损。
- 权威状态留在宿主；DSH通过原生工具读取有界任务摘要、成员、变化和来源。压缩仍由DSH处理。

## 2. 任务图最小契约

| 字段组 | 必须表达的内容 | 禁止的隐式行为 |
|---|---|---|
| 身份与修订 | 会战/任务ID、源版本、规则版本、world/force/task修订、所属阵营 | 凭名称重认身份；过期候选自动覆盖 |
| 承担者与角色 | 当前有效指挥对象、执行叶子、主攻/阻援/掩护/预备/支援 | 同一能力无限供给多方向；两个主要动作同时独占同一叶子 |
| 时间 | 发出/收到/激活/结束，钟点或时段精度、等待原因 | 出击直接算到达；“拂晓”编成确定整点 |
| 依赖 | 有向无环图、all/any、可并行分支、持续保持条件 | 一方向成功提前结束其他方向；支援边授予主指挥权 |
| 空间与资源 | 目标地域/路线、容许角色、储备和耗用上限 | 一个上级点替代全部下级位置；检查通过即凭空补给 |
| 程序判据 | 到达/控制/维持/撤出/保存/库存等已登记谓词，失败/未决原因 | 用模型一句“胜利”写入完成；用伤亡配额拟合史实 |
| 证据与估计 | 来源操作ID、页码、缺载、部署和阈值的估计依据 | 把估计区域写入史料事实；把计划当执行回执 |

任务至少区分待激活、待收令、准备、执行、阻塞、完成、失败、撤销；保存发生时点和原因。一个任务完成后如需继续保持，须明确另设保持约束，不能把曾经占领等同永久控制。

## 3. 推进顺序与现有代码接点

1. `historical_initial/links/constraints`验证史料断言、有效时段与覆盖；新增计算窗口只采已核身份，其余部署/资源进入独立估计。
2. `force_organization/force_tasks/commands`预览任务分工、冲突、能力和资源；复用现有确认摘要与人工优先规则。DSH只提候选，不越过确认直接写账。
3. 在物理推进前激活可执行任务、标明未到场/失联/无资源等待；已知事件落在回合中间时切分内部推进，不能在整轮结束后追补此前火力。
4. `afsim_combined/afsim_campaign`继续产生真实运动、火力和资源回执；`dsh_simulation/campaign_model`仍需守恒和合法性检查。新目标图在**校验后的世界**上由宿主统一判定，不读取模型自报胜负。
5. 新定义下禁用旧的单据点提前终止；原AFSIM目标遥测保留可审计意义，不能一边已结束一边宿主声称其他方向继续。
6. 任务状态、目标进度、命令回执、物理状态与检查点同事务提交。失败或取消保持上次提交态；恢复时不再次入场、扣料、评分或执行已完成命令。
7. UI展示来源日期与当前模拟时钟、方向目标和未完成条件；局部成功、会战未决、来源播放完成明确区分。
8. 已修复`backend/campaign_model.instruction`无条件提示截止回合结算，目标制/旧限时制各有回归；新图隐藏旧联合据点的强制判胜说明。后续任务指令仍须以冻结定义为准，不得重引入与程序结算冲突的时间约束。

### 已实现的目标评分契约

配置冻结在`mission.definition.campaign_plan`，运行进度在世界顶层`campaign_plan`，不把整图交给模型重写。节点1—64个，实际承担单位最多1024个；地域控制/到达、兵力保存、粮弹和既有任务指标有明确类型。循环、跨方承担者、非法来源、地理越界与同轮物理输入篡改拒绝。V1要求双方目标，仅适用于已明确双边条件的场景；单方转移/会师仍用原专项规则，后续另设计单方契约。

`hold_seconds`从首次满足的回合端点开始保守计时；`latch`明确“曾达成里程碑”，不等同当前仍控制。双方独立满足`required_turns`后结算，同时达成可平局。失能终止由显式策略控制。目标状态只评分，不移动、不扣兵、不运补给、不自动下令，也不阻止人工下达与目标无关的合法命令。

DSH复用Native工具`get_campaign_objectives`读取节点或成员，单页最多16。静态配置`plan_hash`与动态`view_version`分开；后续页缺失或过期视图版本拒绝。旧阶段续接入口明确拒绝迁移新图，防止在完整生命周期实现前静默清空进度。API支持指定史料版本与显式参数，向导/DSH自动生成及各场默认迁移尚未完成。

### E03-B2接点与首批失败用例（实施要求与剩余边界）

1. **同一命令链。** 现有`until_arrived`持续移动、准备动作`until_turn`和`commands.prepare/finish`继续承担逐轮执行。新增任务生命周期放在已存在的任务登记内，使用显式新版本；旧`force-task-plan-1`不自动转为可自主执行任务，不新造DSH运行时。
2. **冻结承担者与权限。** 接受任务时冻结当前实际叶子、角色、指挥链和依据；后续转隶不能自动扩兵或继续取得旧权限。任务群名称变化不重新认领实体。来源下级未知余部不参与隐式分配。
3. **依赖与预备队。** 新定义明确起始时点、同方任务/目标前置、完成谓词和资源占用。等待期间预备队的待命须有明确任务授权，不能让批量规划器另行投入；任务与目标依赖分开计状态。一次主要动作占用每叶至多一次，人工单位改令优先。
4. **收令证据。** 区分应用队列已接受与部队实际收令。AFSIM`command_done=0`不能记执行完成；DSH结构回执不得冒充无线电实测。尚无通信模型时明确估计/即时假设，不能凭设置一个时间字段声称延迟已模拟。
5. **取消和故障。** 未执行候选取消不改物理账；已发火力、已耗粮弹和在途运输不回滚。沿现有取消、批次去重、失败前态和原子保存处理；任务状态与命令/世界同次提交，写盘失败不消费队列或依赖进度。
6. **完成与恢复。** 从实际行动/到达及已登记目标读取完成，不因命令字符串为`fire`就认定摧毁目标。阻塞保留具体原因与退出路径。冷恢复、fork和组织变动后复核任务承担者与版本；新图跨阶段仍等待E04合法迁移，不能绕过已有拒绝。

首批用例：两方向主攻与预备队等待→前置完成后释放；人工改令后不自动覆盖；炮兵无弹/未到场明确阻塞；移动跨轮不中断；实际命令未交付不算完成；取消时已有物理消耗不返还；写盘失败同前态重试无双重动作；转隶后旧任务失权；compact后Native分页读全任务；两后端和前端分别实际验收。资源能力分配在E05完整网络前必须明确现有简化边界，不能把申请自身补给称为向其他部队运输。

首版实际已测等待/释放、人工优先、失权、未交付、降级、取消、原子写入、分页和冷恢复；实际Native读任务通过，但“先触发compact再重读”未单独验收。新任务跨阶段明确拒绝，未实现通信延迟和完整共享资源占用；这些检测仍需在E04/E05补齐，不能因上表分项通过而删去。

## 6. 检测记录格式

每项记录ID、作用版本、输入前态摘要、操作、预期、实际、规则/来源、耗时、证据路径及`passed/failed/not_run/not_applicable`。至少核：

- 图判定在两后端共享相同类型和语义；旧局无新字段仍按旧规则恢复。
- 无半提交、重复入场/领料/结算；人员与分类装备整数账精确守恒，连续量按计量分辨率处理。
- 跨阶段、分合兵、取消、导入/fork后身份和任务引用仍正确；未来信息不会被当成当前观察。
- 模型答案与原生工具轨迹分别核对。答案正确但漏读必要资料、把工具调用文本当最终答复仍判失败；保留原失败再独立复测。
- 历史原件未核、坐标未配准、效能未标定各有独立未通过项，不能从软件回归全绿推出历史准确。

对应总验收矩阵D01—D06、O04—O08、C01—C08、M01—M05、A01/A03/A05及U01/U03/U05；全45场推广仍逐场验收，不能凭万家岭通过统一宣告完成。
