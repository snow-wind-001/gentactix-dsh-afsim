# 渡运指挥生命周期与连续账复核

本次修复桥成后整建制渡运的控制边界。没有新增历史实力表，也没有把后续通行模型扩称为舟筏强渡或桥头堡争夺。完整历史业务仍为 **0/45**；19份部分档案、395项参考记录和26场缺此格式的范围不变。

## 已修复的问题

| 问题 | 现在的行为 |
| --- | --- |
| 撤销后向同一坐标重新下令可能继承旧工作量 | 新确认命令绑定新的宿主身份，重新排队；旧轮已耗容量保留在原轨迹 |
| 再次保存未改动的持续命令会生成新身份 | 前端保留当前命令ID，后端核对动作、目的地、持续方式等后保留原命令 |
| AFSIM编译只传坐标，丢掉宿主控制身份 | 编译器传完整已规范化命令，原生回执保留任务身份 |
| 撤销只改变界面队列，底层任务没有明确状态 | 下一轮原生指令交付产生撤销回执；DSH独立模式提交估计回执并接受守恒检查 |
| 通信延迟时仍显示已执行撤销 | 未交付显示暂停并保留待撤销输入，下轮重试；不伪造交付事件 |
| 反事实给同一命令生成新身份，可能造成虚假差异 | 动作及目标完全相同时绑定事实命令的控制元数据；主局保持不变 |
| 当前任务工作量被称为累计工作量 | 改称“当前任务已服务工作量”；重新下令不会改写旧轮消耗 |
| DSH重试用整轮零服务规避入口事件错误 | 设施开放、待服务移动本轮能到入口且没有任何其他编组/物资服务时，拒绝无故全部零服务；关闭设施仍可合法为0 |
| 新命令的计算起点与旧撤销任务混淆，重试草稿混入宿主ID | 只读 `crossing_inputs` 明列起始工作量、总需求、方向及路线；重试输出示例移除宿主控制字段，原任务历史保留 |
| 直线距离小于机动预算就预测本轮到达 | 渡运场景明确另计排队与通道时间，不再以直线剩余0公里暗示到达 |

## 状态与引擎边界

设施仍为冻结的 `formation-crossing-1`。新增的 `formation-crossing-task-2` 在任务中绑定宿主命令 `intent_id`，并支持 `cancelled`；旧task-1和旧存档仍可读取。旧未绑定持续命令不在载入时推测身份或改写进度。

排队时可以撤销，已消耗服务量不退回。已进入通道的编组不能靠撤销恢复到原岸；新指令可以继续向出口侧行进，不再支付已完成服务，回撤须先抵岸。该约束不代表真实渡运人员已逐个分岸，人员与装备仍按整建制账管理。

用户编辑队列不会直接改写战场。原生执行在现有WSF指令交付时点确认撤销，并由原生输出任务、事件和容量；Python只编译输入、核验回执和提交检查点。DSH独立执行保留同样的账目与位置约束，来源标为模型估计。没有增加Python过程解算器或新的智能体调度框架。

带该模型的新AFSIM执行采用运动版本7；不带该模型的旧路径仍为版本3。旧版本6可读取，但拒绝跨执行版本进行反事实归因。
