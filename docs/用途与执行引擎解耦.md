# 用途与执行引擎解耦

后续用户已明确纠正：回溯分析与历史战局推演均不得使用局部代表编组；只有合成教学可使用这种派生方式。3.7.0的引擎选择已接通，但历史初态未达标，当前历史入口复用局部模板的实现是缺陷。本文件的引擎解耦约定继续适用，初态修复以[全场景审计](历史初态全场景审计-2026-10-27.md)为准。

## 本轮约定

三种用途均独立选择DSH或DSH+AFSIM。用户已明确：历史战役回溯分析严格按有来源的事件顺序重现；历史战局推演及合成教学演习允许改变过程。关闭AFSIM时不能调用模拟器，也不能把Python教学解算冒称DSH推演。

新增`product_mode=analysis|historical|synthetic`与既有`execution_backend=narrative|afsim`正交保存。旧存档和未提交该字段的API保留原有兼容行为。界面使用DSH称谓，`narrative`仅为已有接口枚举。

## 六种组合

| 用途 | DSH | DSH+AFSIM |
| --- | --- | --- |
| 回溯分析 | DSH解释当前来源事件，关键事件/次序由来源帧约束；解释另存，不能改写源帧 | 原有AFSIM来源帧回执路径 |
| 历史战局推演 | 从同一史实基础生成局部配置，DSH估计过程，允许改变决策及结果 | 从史实基础生成局部配置，AFSIM计算已登记规则；历史缺载参数仍标估计 |
| 合成演习 | DSH生成可编辑初态配置并估计后续运动、战损与补给；程序只校验账目、命令和目标 | 同一配置编辑与来源约束，AFSIM装载和计算 |

关闭AFSIM的派生配置仍经过DSH原生skill与结构验证，草稿记录实际验证引擎。切换引擎后原验证失效；创建时核验草稿引擎。DSH状态更新不得改初始投入基数、规则定义或单位身份；失败、取消与过期版本不提交。

## 前端切片

保留LaunchScreen的战役选择→参数配置。用途与引擎均可单独更改，不再用隐蔽确认项阻塞历史入口。需要派生配置时复用ScenarioComposer；“生成配置并进入”连接实际skill和验证，编辑后需要重新验证。按钮旁说明待办，错误可见，取消和收起保留草稿。沿用现有配色、折叠地图与窄屏规则。

工作台、导出、恢复和单位回执均按实际用途/引擎标识。DSH估计不显示为AFSIM回传或确定性教学结果。回溯仍不接受改写来源帧的作战命令。

## 验证门槛

六种组合的API与浏览器入口；DSH路径断言不调用AFSIM和Python战斗解算；源帧乱序/伪造拒收；DSH人员装备不守恒、漏编组、篡改规则和取消不提交；引擎切换使旧验证失效；真实DSH与AFSIM各有运行证据；最终安装包及本机入口验证，原对局和模型配置保持完整。
