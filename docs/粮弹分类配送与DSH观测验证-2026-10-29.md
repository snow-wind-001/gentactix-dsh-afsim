# 粮弹分类配送与 DSH 观测验证

## 行为与边界

此前到货被粮食、弹药剩余容量的较小值限制，出现满弹不能补粮。新增冻结配置 `supply_distribution.version=split-stocks-1`，新历史想定模板默认启用；旧定义和存档没有该字段时保留原规则，不静默迁移。

仓库 `commodities.food/ammo` 独立扣减，未配送物资留仓。两类共享运输载重、路线和燃油约束，运力不足时按配置优先配送粮食或弹药。初始每包拆为各一工作量粮食与弹药，质量份额是明确的建模估计，不是历史重量。`stock/delivery` 是加权质量当量，不能当作任一类到货量。

AFSIM 原生 WSF 分配物资并输出分类回执；Python 编译、解析、验证守恒，不替代推演。DSH-only 模式提交 `dsh-resource-ledger-2`，缺少分类收支、凭空补货、超过库存或运力上界时拒收。普通粮弹工作量与分类炮弹、油料、维修件继续分账。

DSH 观察、跨回合汇总、战报和前端均区分两类到货、质量当量与消耗。修复了旧提示仍宣称“一份一粮一弹”、汇总忽略新回执和元数据误标旧账本版本的问题。只读预算不是自动配送触发器；工具公开模型质量换算参数。

## 原生执行

11 次真实 AFSIM 执行通过，经 DSH 原生 MCP 控制通道，禁止 Python 推演替代。证据：`.cache/qa/split-supply-native/1793282834226046686/result.json`。

| 情形 | 原生结果 |
| --- | --- |
| 弹满、粮缺 | 每单位粮到货8，弹到货0，质量当量4 |
| 粮满、弹缺 | 粮到货0，弹到货8，质量当量4 |
| 两类不足 | 各到货8，质量当量8 |
| 命令未送达 | 仅被动补粮2，没有主动补给增量 |

| 连续第二轮 | 库存连续，补粮后缺粮债务按规则恢复 |
| 旧版本 | 保持旧档满弹阻止补给的行为 |

检查输入世界不变、原生成功、缺失回执拒收及序列化恢复。估计参数不构成历史损耗标定。

## 真实 DSH 链路

台儿庄局部 QA 使用历史番号，但人数、位置和性能为测试估计。DSH 为双方三单位选择 `resupply`，AFSIM 执行 T1→T2：每单位粮到货8、弹到货0、耗粮2、余额14，时间00:30→01:00。引擎约11.4秒、9,814观测token，AFSIM约1.98秒。见 `.cache/qa/split-supply-ui/live/after.json`、`result.json`。

真实轨迹含 `evaluate_action`、`get_afsim_observation`、`get_afsim_changes`；请求为 medium、65,536输出上限。DSH 控制行动、AFSIM 产生状态、现有地图前端显示提交结果，未增加替代模型客户端或仿真器。

首次问答核心分类账正确，但把预算说成补给触发条件、称吨数无法换算。补充观察字段后，在同一已提交战局重新只读问答，明确预算不自动触发配送，并核对第31师运输量：

`4×0.25 + 48×0.01 + 4×0.01 + 4×0.008 = 1.552` 模型吨，与原生 `delivery_tons_milli=1552` 相符。复核约41.6秒、28,327观测token，世界未变。见 `reanalysis.json`、`reanalysis-checks.json`，不是速度对照实验。

**自然语言扩展解释仍需复核**：第二次回答把可由份额推导的独立粮食吨数列为未知；还把决策前预算14与轮末预算12视作待核差异，前后快照已确认其时间点不同。初始QA检查点缺完整第1轮轨迹，不等于没有原生执行。这些解释没有改状态，但不能宣称所有分析准确。
