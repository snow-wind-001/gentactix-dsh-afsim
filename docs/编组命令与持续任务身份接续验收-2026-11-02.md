# 编组命令与持续任务身份接续验收

本轮接续 K05 的会话命令、组织和持续任务。新增 `formation_session.prepare`，在原有完整世界候选上，生成可核对的**脱离运行会话的命令与任务候选**。普通会话导入和实际执行仍拒绝这种候选：原生平台重建、保存失败恢复及运行中分合界面尚未接通。45场270个完整历史窗口仍未验收。

## 身份、命令及原生会话

登记根账 ID、组织叶子 ID、会话命令 UUID 是三个不同标识；现在分别生成映射，不依靠名称猜测替代关系。复用现有命令 ID 生成器，新 ID 绑定会话与代次，未选择的单位保持原 ID。旧 ID 留在注册表，标为退役以继续查阅原决策与回执。

| 内容 | 接续策略 |
|---|---|
| 人工命令 | 明确派给新身份，保留动作、目的地、持续条件和原创建时刻；生成稳定且独立的新命令 ID |
| 原命令及决策 | 原命令归档为身份交接，不能当成用户取消或已执行；历史、决策日志、既有回执保持原 ID |
| 单位智能体 | 配置移交新身份，原 `agent_sessions` 原样保留；新单位首次实际决策时由现有 DSH Native AgentRegistry 建立独立会话，不复制旧会话 |
| 临时任务群 | 成员展开到互斥新叶子，层级和群 ID 保留；直接指挥关系不同的单位不能隐式合并 |
| 外部目标 | 合并目标可映射到唯一新实体；单一攻击目标即将被拆成多个实体时须先明确取消或重新选择，不能任意替用户选一个 |
| 外部资源预约 | 航空资源池请求不能随请求单位拆分而复制；当前须先明确新的请求单位 |

合并还要求原命令语义一致，不能将“有命令／无命令”或不同人工指令静默择一。上述拒收保留原局，属于明确的当前操作边界，不据此宣称任意战时改编均已支持。

候选会话复用 `session_store.serializable` 的检查点边界：活动观察器可能含线程锁，适配器与进度对象留在宿主，不随候选复制或持久化。没有另建会话存储服务。

## 持续任务、计数与权限

原任务正文、完成判据、前置、定义摘要保持不变。新增 `identity_origin` 固定原承担者和指挥链，当前承担者另沿经过审计的身份映射接续；任务角色及目标在每次命令准备时解析。不同角色、不同任务范围或不同人工接管状态的合并明确拒绝。

原已交付轮次作为继承计数保留。拆分出的每个当前承担者各自继承，**不得将共享来源的计数相加**；同地合并取来源计数的最小值，以保持“所有承担者均完成最低轮次”的判据。原始逐成员状态仍保存在接续回执中。新身份的 `last_order_id`／`last_receipt_id` 清空，不把旧实体回执复制成新实体已经执行的证明。

后续仍由原 `force_task_execution.prepare/finish` 和命令回执结算；没有在转换时推进任务、发奖励或增加执行次数。已终止任务原样保留，不改写历史承担者。成员分页新增来源说明，区分继承轮次与新实体实际交付。重复回执负例还发现任务结算可重复接受同一承担者回执，现已先整批检查重复再结算，拒绝时不修改任务状态；不是声称真实运行曾发生重复交付。

## 回执、合法性检查及默认限制

命令状态的 `formation_handoffs` 保存转换前命令／组织元数据、明确映射、修订及候选摘要；前态不递归复制旧交接列表。每条映射使用已有命令身份生成器独立重建，不能依赖重新计算摘要掩盖伪造映射。当前同一时点的末次交接还重建命令及组织候选。正常后续命令和组织修订分别核对，允许合法编辑，禁止修订倒退；不把此机制当成完整历史轨迹认证。

`commands.validate_saved` 接入映射核对。新增内部只读合法性范围，进入时验证这一个候选世界，退出时核对其摘要，中间复用该证明检查多条命令；不填充普通战局校验缓存。范围外及范围内的另一份世界仍不能绕过运行限制。此范围只被候选命令检查调用，没有 JSON／前端开关，也不构成平台执行授权。

现有 HTTP 和 DSH Native `preview_force_conversion` 同时返回有界 `session_continuity`：命令／组织是否准备、身份数量、接续任务数、是否复制原生会话及是否已执行。完整候选会话、映射和历史回执留在宿主，没有另写智能体编排或模型战场。
