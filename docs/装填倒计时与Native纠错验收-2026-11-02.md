**结果：计时校验、Native拒收纠错、合法后续射击和界面秒级显示通过；最终源码的独立复测还完成了原持续任务。全功能和完整历史验收仍未通过。** 两个分支均继承早先明确标注的固定QA兵力、装备、几何及目标参数，不证明史实部署或本轮AI配置生成。

## 已复现的问题

上一轮16个真实回合帧中，DSH 的 T2—T9 共8帧存在同一问题：日军第106师团执行 hold，经过900秒后，`formation.reload_remaining_s` 仍为60，按现有模型应为0。原始存档保留，没有补写或修复历史输出。

旧验证器在没有 `fire_ledger` 时直接返回，因此跳过了无射击回合的装填流逝。同时，射击校验只核对回执与状态字段相等，没有核对末次开火时刻与期末装填的关系。`archived-candidate-rejection.json` 记录同一真实错误帧在旧验证器下被接受、在新验证器下被拒收。

## 修复规则

- `reload_remaining_s` 是权威秒数；只有缺载该字段时，才将旧 `reload_remaining` 周期计数乘以 `artillery_cycle_s` 换算。两者不可按同一单位解释。
- 没有地面射击或实际发射次数为0：期末为 `max(0, 轮初剩余秒数 - 本轮秒数)`。这也适用于待入场、失能和非射击行动；与现有 AFSIM 轮末规则一致。
- 有实际发射：期末为 `max(0, 末发时刻 + 对应射击周期 - 本轮秒数)`。不足1秒部分按原生整数回执的精度截去。
- 轮初仍有装填时，模型必须在 `unit_updates.formation.reload_remaining_s` 明确提交期末值，包括0。错误结果通过现有 Native 预览反馈拒收，宿主不替模型改状态。
- 没有地面射击不添加虚假的 `fire_ledger`；离线旧式射击响应的兼容入口仍保留。导入、恢复检查点不追溯改写旧状态。

## 回归与真实测试

新增6项回归覆盖真实60秒错误、部分装填、旧字段换算、权威字段优先、非射击和不可用单位、末发装填关系，以及既有反馈重试。最初5项使用保存的旧验证函数运行，得到10处断言失败、无测试错误。真实测试又发现缺少 `action` 后连续收到笼统反馈的问题，追加第6项回归先失败，再将错误消息改为明确列出缺少／多余字段。最终 `verify_fire_process.py` 共23项通过。早期测试夹具曾遗漏战役过程字段，修正的是夹具，原计时校验要求没有放宽；相应日志保留。

真实测试从上一轮 T1 的完整实态经普通导入、开放分支接口复制，使用独立 SDK 会话。首轮有意请求一个保留60秒的错误候选，用于测试拒收链路；这不是声称模型再次自发出错。只审查公开工具调用、返回和战局结果，不读取或导出模型私有思考。

真实分支为 `0d0d390433f6`。T2 中错误预览被拒收，模型显式改为0后重新预览、提交；正文另一次触发库存断言筛查，修正正文后通过。后续射击脚本最初误取了来源案例后续分兵后的身份，队列接口正确返回422；修正的是 QA 身份解析，来源T1和已提交T2均保留。
