# 车桥完整史实推演实施与验收计划

本计划承接2026-10-29的真实失败案例。目标是完成一场有来源、连续且可控的攻坚—打援战役；旧对局、冻结资料、模型配置和当前用户安装保持不变。未通过前不打包、不上传、不宣布完成。

## 验收口径

- 严格回溯必须具备可辨认的部队与部署依据；无部署的事件阅读不能标成完整战场重现。估计部署须单独标识，不能改成史实点位。
- 分开保留5—6日、5—7日及后续扩展战果口径。50／52团、500／600余守军及192／238伤亡等异文逐项登记，不相加或取均值凑结果。
- 完整核心流程覆盖夜间初攻、镇内分割、炮兵接近、外围分批增援、阻援与侧击、夜间争夺、残余守军撤离和局部控制；具体钟点只使用来源支持的精度。
- 原生执行、人员与分类装备守恒、粮弹收支、持续命令及阶段衔接必须连续。接敌、俘虏与撤离由对应行动及规则产生，禁止写入固定历史减员。
- 战役目标按攻坚和打援分别计算，局部失败不能冒充全役历史结论。同初态改令必须可能产生不同结果；不强制红方获胜。
- 真正未知的名册、装备与阵地继续未知。通过一场过程验收不等于45场初态档案完整或武器效能已全面标定。

## 实施分片

1. 先写失败回归，新增版本化全程参战与阶段档案，保留旧版本及来源异文。完整模型未具备时阻止入口宣称就绪。
2. 扩展既有AFSIM聚合模型所缺的入场、攻坚与受降能力；继续使用WSF执行，不新增Python战斗执行器。必要计算分队沿用现有守恒模型。
3. 复用DSH原生skill和配置工具构建全程初态，明确在场、集结与后续部队。补齐可计算的多方向战役目标与阶段观察，不重新构造智能体传输或工具协议。
4. 修正前端回溯入口和空态：两个地名参考圈不算部队；缺部署明确显示缺项。具备有效初态后共享现有地图、军标与来源展示，区分史实、估计、计划和已执行。
5. 完整真实推演及同初态对照，逐轮核账，DSH真实读取并解释；宽窄屏验证；独立进程恢复后结果相同。保留失败记录，缺口未解决不降低门槛。

## 复用与控制

后端沿用`historical_initial`、`historical_operations`、`formation_parts`、`missions`、`afsim_combined`及现有命令回执。前端沿用`LaunchScreen`、`HistoricalScenarioComposer`、`MapView`和`HistoricalRosterPanel`。来源和运行状态由宿主固定，DSH按需读取；保持high／65536。

所有新数据和API先离线回归，再进入独立测试局。停止自有后端前必须新鲜核对所有会话与构建均不活跃、启动参数匹配、全部世界和命令已保留；不能因模型等待而重启。
