# 运行中实体分合兵前端接入方案

本轮范围是把已有实体转换事务接入Vue工作台。45场资料标定及270个完整历史窗口继续按总规划推进；本界面不能代替这些验收。保留配置、已有对局、原QA和历史轨迹，不发布或替换安装版。

## 入口与组件

在“兵团”侧栏加入独立的“实体分合兵”区，明确区别于原临时任务编组。新增 `FormationConversionPanel` 负责编辑、只读预览、确认入口和同请求重试凭据；`ForceOrganizationPanel` 保留历史树及任务群职责。App通过提交回调负责API写入、全局忙状态、读取新快照和选择交接，组件卸载不改变提交职责；CommandCenter按当前身份映射更新选择及清理旧草稿。地图重叠单位继续使用现有定位名单，检查转换后可选全部子单位。

## 数据与权限

历史战局必须选择当前冻结史料中本阶段在场的直接下级，不能复用合成模式的自由命名请求。使用现有编制视图的历史父子链、在场状态及覆盖说明，不按单位名称猜身份；下级覆盖不完整时显式保留一项未分配余部。没有可用下级时解释资料缺口，禁止虚构番号。历史分配量仍是操作者注明依据的估计参数，不能冒充史实兵额；合成模式保留自由命名分队。

复用 `commands` 的当前执行单位、人员投入数和可指挥权限，以及组织视图的四项修订信息。分兵选择一个执行单位，输入2—32个分队的标签与投入数；不把存活人数当作原投入数。合兵选择多个单位，兼容、同根、同地等限制由既有后端判定，不在前端重写算法。

`conversion-preview` 接收kind、unit_ids、allocations、assumption及当前回合／命令／世界／组织修订。预览显示前后人员、装备、库存总账、建议身份和任务连续性，明确尚未保存、未执行物理过程。分页使用同一view_version。修改输入或外部修订变化使预览失效。

`conversion-commit` 使用该预览及固定32位commit_id。网络断开或5xx时保留完整原请求，提供同请求重试；禁止换ID重提。重试可能已经保存，不允许把旧输入直接当新转换。409／422清晰说明重新预览；确认成功后读取当前快照，不按本地算出的世界修改地图。

## 状态与选择

状态为编辑→预览→提交中→成功，或结果待核实／明确拒收。异步响应校验会话和输入代次，旧会话响应不得覆盖新战局。提交与下一轮等写操作共用工作台忙状态；不增加第二个状态仓库、仿真器或DSH传输层。

使用 `current_command_map`，不把原始command_map当当前身份。多后继不自动挑一个；显示候选名单，操作者明确选择。清除旧单位目的地、目标、自然语言草稿和预览，避免分兵后沿用过期命令。任务转移结果与人工接管影响必须可见。

## 可访问性与显示

使用现有侧栏、颜色与控件；输入有独立标签，错误用alert，进度和保存回执用status。全部功能可通过键盘操作，预览确认和重试按钮名称不同。长预览内部滚动，900与1440像素宽度均检查侧栏不越界；不新建遮住地图的常驻大型面板。

## 实施与验收

先记录现有界面缺少入口的浏览器失败，再接入类型、API和组件；后补主界面刷新与当前身份选择。两后端在隔离存档上通过真实HTTP完成：只读预览、修改失效、确认、同请求响应丢失重试、分兵后合兵、拒收过期修订和刷新恢复。检查时钟、人员装备库存守恒、历史轨迹不回填、任务连续和所有当前单位可选。

运行前端typecheck／build、相关回归与全部根verify脚本；浏览器截图和正常下一轮执行另存证据。模拟网络故障必须标明故障注入，不能把它算作模型或后端自发失败。保持DSH原生会话、工具、取消、轨迹和预算机制，不自行实现对应运行时能力。
