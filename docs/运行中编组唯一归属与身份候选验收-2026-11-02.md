# 运行中编组唯一归属与身份候选验收

本轮推进 K05 的唯一归属与身份接续基础。已实现根账、互斥份额、转换事件重验及身份参考视图，并把归属验证接入当前只读预览。**尚未把候选执行单位写入运行战局**；命令、持续任务、目标、参与登记和两后端迁移仍未完成。完整 45 场的 270 项历史窗口不据此通过。

## 原有缺口与修正

上一轮的转换提案能证明一次分配的数量守恒，单靠 `origins` 计数不能证明同一份额没有被复制后改 ID 再使用。另经代码与对照测试确认：原宿主冻结身份校验不检查单位额外携带的 `runtime_allocation`，因此伪造的资源尺度元数据可能随检查点被保留。

现在 `missions.validate` 首先调用归属验证。单位自报运行中分配却没有唯一归属登记时明确拒绝；旧战局没有此字段时保留原结构和原规则。`legacy-metadata-ab.json` 记录领域校验对照，`legacy-checkpoint-ab.json` 进一步使用完整真实 QA 检查点验证：关闭新检查时原完整检查点校验接受该额外元数据，开启后拒绝；没有修改检查点文件。没有依赖一次摘要相等来认定归属正确。

## 唯一份额和事件重验

`gentactix/formation_registry.py` 从本局冻结的 `mission.definition.initial_state` 建立根账。它登记的是投入与资源归属，区间不是单兵姓名、装备序列号或历史实到证明。

| 内容 | 验证方式 |
|---|---|
| 人员投入 | 每个根账的整数半开区间完整覆盖、不重叠；伤亡仍占原投入份额，不变成可再次投入的人数 |
| 分类装备投入 | 每一类独立登记整数份额；车辆不按人数当作同一种资源计算 |
| 粮弹资源尺度 | 使用初始份额的有理数比例，细分后不重置为一，不按幸存人数重新归一化 |
| 当前损耗与库存 | 转换提案须与权威当前实态完全一致，并重算前后人员、装备、库存及余量 |
| 身份与来源 | 原身份消耗后不能重复使用；新身份不能重复或与已用身份冲突；固定字段及来源说明保持受审计 |
| 时序与用途 | 事务序号须为整数，回合和累计时钟分别不得回退；历史／合成规则和冻结史料不能换用 |

登记仅保存版本、冻结定义摘要、事件序列及其摘要。有效叶子与归属由事件重验推导，没有另存一份可独立改写的活动名单。对篡改后重新计算摘要的登记，仍重新计算提案及份额，拒绝重叠、遗漏和重复消费。

`stage` 返回脱离主战局的候选及旧新身份映射。未参与转换的红蓝单位使用其**当前**伤损、库存和冷却，不能从旧事件模板恢复。`reference` 提供经核对的不可变身份参考，供后续三个冻结身份校验点共同接续；它不能代替当前物理态势。

## 历史父级与未知余部

历史正例复用现有会战窗口的“选择父级、下级作为覆盖参考”能力。私有 QA 窗口绑定万家岭 1.3.0 的 10 月 7 日来源，选第74军为执行单位，第51、58师保留为其覆盖参考；其余来源身份逐一说明。没有改动发布的窗口、初态或历史事实。

随后按有来源且本阶段已核在场的下级，生成第51师、第58师和“未分配余部（估计）”三份候选。10000 人投入、4000／4000／2000 分配以及部署全部是明确 QA 估计。设定当前 9800 人、战斗减员180、非战斗减员20和20件运输装备中的14件可用／3件待修／3件毁损，转换后各账精确相等，原史料快照不变。

默认局部入口选择最低层已载单位；需要父级执行时应使用有完整身份处理的显式会战窗口。不得为了分兵放宽“有来源且已在场”条件，也不能把这份私有测试窗口作为默认历史想定发布。

## 45场资料结构盘点

本轮另扫描45个默认档案及56份现存版本，全部可读取；这是本地资料结构检查，未重新核验原始史料，也不代表这些场景已经能运行分兵。

默认档案中，只有5场在某个阶段同时记有“已核在场的父级”和至少一个直接在场地面下级，共13组父级—阶段组合，覆盖状态全部未知，没有完整下级覆盖声明：台儿庄1组、徐州3组、第一次战役6组、第五次战役1组、湘江2组。计入非默认版本后有6场，增加万家岭1.3.0。候选下级的兵额、装备实数均缺载。

这说明引擎具备分配算法后仍不能给所有历史场景自动添加下级。默认档案的其余40场没有上述来源组合；若要历史分兵，应先补直接隶属、阶段在场及覆盖边界，数量缺载另作估计。非交战转移、集结及接收按各自任务适配，不为凑层级强造战斗单位。优先使用有来源组合的试点，并为真实父级选择准备显式窗口。

逐场清单：[CSV](会战级分合兵资料结构盘点-2026-11-02.csv)、[含56版明细的JSON](会战级分合兵资料结构盘点-2026-11-02.json)。命令：`PYTHONPATH=. python tools/qa/formation_source_audit.py --out docs/会战级分合兵资料结构盘点-2026-11-02.json`。非默认版本组合按版本统计，不能相加当成更多真实战役；条目缺失也不表示历史上不存在下级。

## 测试与后续接续

新增归属回归25项；转换预览再补重复名称及有界归属摘要2项。相关140项通过。测试包含嵌套细分、部分／完整合并、初始计算分队再次细分、当前损耗延续、未选单位保留、冷恢复、用途及版本约束、同名冲突、重复消费、伪造归属和未完成迁移的拒绝。新组件在 TDD 中发现的时序、布尔序号、类型拒绝及名称问题与原宿主缺口分开记录。两次历史夹具输入错误分别因阶段及地域不匹配被正确拒绝，修正的是 QA 输入。

真实 Native 问答已通过，约24.74秒。公开工具调用／结果记录证明模型实际读取了观察和两页预览，分页版本及归属摘要一致；模型回答现有8661人、累计战斗减员1339人、装备投入164件、当前6实体、候选7实体，并明确未实际分兵。完整候选在宿主拒绝的具体位置是尚未迁移的参与登记，归属本身已通过，记录为 `host-admission-review.json`。

最终 `python verify_all.py` 已结束：**139／139组、1596项unittest、0失败、0跳过**，包括上下文退化检查与干跑探针。各组耗时合计964.06秒，不是整体墙钟时间。7份冻结源码前后相同，68项受保护文件及3份来源检查点字节未变。

证据在 `.cache/qa/formation-ownership-2026-11-02/`：`final-offline-gate/results.json` 及全部分组日志／探针、`validation-summary.json`、`actual-preview-review.json`、`native-chat-review.json`、`native-tool-review.json`、`host-admission-review.json` 和各阶段红／绿回归日志。只读检查点复核不等于新物理回合、完整历史或实际分合事务通过。
