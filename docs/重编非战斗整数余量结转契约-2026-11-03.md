# 重编非战斗整数余量结转契约

本工作包服务于会战级分合兵与连续保障。此前把每单位的小数余量相加后若达到1即拒绝合并，避免凭重编制造减员，但限制了正常操作。本契约先接入已有时间保障的非战斗余量；战斗、阵亡分类、旧每回合模型与装备损伤整数债仍独立登记和验收，不据此宣称任意合并完备。

## 状态与来源

- 继续使用唯一的`unit.sustainment.noncombat_remainder`，不增加第二份计量库存、影子战场或执行器。
- 仅正式合并产生跨整数负荷时，在既有`runtime_allocation`登记`support_remainder_policy="deferred-support-exposure-1"`；后续拆分／合并继承。普通旧单位不自动迁移，未登记的余量≥1仍拒绝。
- 标记不代表真实伤员名单，而是同一根编制在聚合模型中尚未折为整人的估计失能负荷。它随原身份／归属账与转换提案绑定，模型不得添加、删除或改写。
- 负荷须为有限非负数且小于累计投入人数；根身份、人员和分类装备所有权仍由既有编制账校验。

## 转换与结算

1. 拆分按既有份额分配，合并按精确总量相加。当前人数、累计减员、粮食质量、装备、任务、时钟和已有轨迹均不因转换而改变。
2. 对已登记单位，只有非零物理时段（至少1秒）中出现新的有效失能暴露时，才用既有保障公式对累计负荷取整。新增失能仍受可用人数上限约束，未折整小数继续保留。
3. 满粮／无新暴露、无可用人员及0.001秒装载探针不消耗这份待结算负荷。单纯合并或经过时间不能变成新的战死；记为非战斗失能，不混入阵亡。
4. 定时补给按每段分别结算，已折整负荷不得在后续到货／同秒结算重复使用。阶段、分支、存档及冷恢复保留状态；再拆分不丢负荷。
5. AFSIM继续在WSF中执行；DSH提交人员与保障回执，宿主只核对方程、收支和来源。错误候选拒收，不由Python代写物理效果。

## 检测要求

- 红测先复现0.6＋0.6合并被拒；绿测验证合并为1.2但人数、库存、时间不变。
- 有新增暴露时下一段正确结算；满粮／零时长／无人时保留负荷；伪造标记、负数、无穷、越界、错版本及双重结算拒收。
- 两次分合、部分合并、检查点、分支和阶段边界守恒；旧提案重新计算及旧局恢复保持兼容。
- 原生AFSIM与真实DSH均从实际保障过程得到分队余量后再合并，验证后续人员／资源／任务；不得把手工种入的余量冒称模型或战史结果。
- 完整离线门禁与正常前端确认流程后再记录通过；测试使用隔离目录，不修改既有五份验证局、用户配置、默认初态或安装包。

本工作包通过也不等于45场／270格完整历史验收通过，历史编制、部署、后勤、地形与损耗标定继续按原总计划推进。
