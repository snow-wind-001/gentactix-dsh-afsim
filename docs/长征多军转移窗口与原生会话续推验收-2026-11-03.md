# 长征多军转移窗口与原生会话续推验收

本次推进会战改造的非接敌分支：新增右路军四军转移窗口，复用现有 DSH 原生单位工具、入场模型、AFSIM 执行与目标图。四轮计算已通过前端操作、原生会话冷恢复续推和账目复核。**这是显式估计参数下的转移功能验收，45场／270个完整历史验收格仍未通过。** 未上传、打包或替换安装版，未改用户配置及既有对局。

## 先前判断的校正

前次目录复核将 LM06、LM15 的累计名单选择失败概括成“缺少转移模型”，表述过度。已有 `historical_operations.partition`、`missions.goal_winner` 和分片构建器支持有来源的局部单边转移；原来的金沙江案例已经使用这一能力。真正未接通的是会战窗口、会战过程的目标类型和多单位目标图。

普通累计名单的双方检查保持严格。新例外只来自冻结历史阶段的 `non_contact_transfer` 声明，不能靠删除蓝方或设置一个任意单方开关绕过。

末轮发现新增版本目标说明仍沿用旧“至班佑”文字，已仅校正**本次新增**的1.1.0目标说明、范围及来源定位。旧版本绑定保持原字节；不修改已保存计算定义、数值、窗口或历史初态正文。生成器现可用 `--check` 检查新说明，不默默覆盖已有版本。

## 实现

1. 会战窗口逐阶段核对同一参演方，拒绝混入未声明的交战阶段或隐藏来源记载的在场敌军。
2. 会战过程允许转移／渡运目标，保留实际入场与资源约束；非接敌范围不设置虚构阻援或受降。
3. 同一 `campaign-objectives-1` 目标图支持参演方的到达、兵力保存与随队资源目标。未参演方目标为空时恒为未达标，进度恒为零；无敌军不自动获胜。参演方全部失能时无获胜方。普通双方结算语义保持。
4. 配置模板保留每个军的独立到达目标，并生成保存与资源条件；地理、最少人数、保存比例及粮弹阈值留待显式填写。DSH继续使用已有分片配置工具及运行时查询，不新增执行器或会话调度框架。
5. 前端只显示参演方目标／进度，资源阈值可编辑，非接敌配置不展示受降开关；原生查询也返回参演阵营。

真实 AFSIM 首次运行暴露了一个额外缺陷：没有阻援区时生成 `bool campaignRelief=;`，脚本无法编译。已通过回归先复现，再将空集合生成明确的 `false`，与宿主对照状态一致；未以Python物理执行替代失败运行。
