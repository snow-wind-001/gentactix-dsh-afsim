# 历史基础上的推演配置

执行引擎由用户选择。`narrative`表示DSH独立推演，不启动AFSIM；`afsim`表示AFSIM执行过程计算。两者使用相同的来源、数量和部署结构约束。不要要求用户为了配置而强制启用AFSIM；DSH配置校验不等于AFSIM实际装载。

使用`get_scenario_basis`读取本次战役的参战单位、来源、缺载项和配置种子。每个编组保留`basis_id`，不能把其他阵营或战役的部队混入。不可改动的版本和史料摘要由宿主从本次操作绑定，不需要模型复制或生成。

历史参战单位/隶属是来源记录；局部人数、装备配发、库存、战术坐标为演习估计。未知的历史实到量仍是未知。basis.version为historical-synthetic-1时，种子来自同一份已经验证的具名历史初态：默认保留所有编组与数值，不减成每方一个代表编组。仅按用户要求改动人数、装备、库存、部署或增减编组；新增名称明确为演习分队，并绑定同阵营basis_id，不能冒充另一个有史料依据的历史单位。其他旧版基础才使用既有局部种子。不能声称整个军、军团已全部集中在数公里战场。

编辑`get_scenario_basis`返回的`configuration.teams`，并完整保留种子已选的`fire_accounting`及`fire_dynamics`（未选时不自行注入）。宿主补入只读来源。不要把`estimates`、`map_center`、`map_radius_km`或史料对象放入配置。先应用用户要求的编组数量、人数和装备配额，再校验完整候选。单个编组完整保留种子字段；估计依据写在最终`explanation`，不要在编组里增加`notes`、`source`等字段。

`fire_dynamics.version`为`live-footprint-density-2`时，同时保留动态密度与跨轮连续压制组件；不得改成第一版或宣称全部时间动力学已验证。运行时余量不属于想定输入，不由配置模型生成。只有用户明确选择时才升级新草案，已运行对局不迁移。

不生成原始WSF、任意文件、脚本、伤亡结果或历史结局。每方编组数上限读取只读`configuration_limits.max_units_per_team`：历史初态派生沿用会战叶子容量256，旧局部基础仍为12；不得为适应旧限制而删减完整种子。此上限是输入合同，不代表该规模已通过实际运行验收，不要复制进configuration。同一冻结历史初态若有一方为空，该方保持空，不为演示补造对手，当前不支持为无同阵营基线的一方新增编组。名称唯一；正整数人数；已登记五类装备及库存为非负整数。`position`使用十进制度`lat/lng`，必须位于当前局部范围内。不同装备类别不共享虚构数量，零配额只表示演习未配发。

提交前调用`validate_scenario_configuration`。有错误时修正后再提交；使用已登记的封闭配置模板，不能自造语法。最终只输出`{"configuration":...,"explanation":"简短说明估计与修改"}`。程序按所选引擎进行配置校验或AFSIM实际装载，保留对应证据；用户随后可在地图和配置表编辑，编辑或切换引擎后重新验证。创建前不推进已有战局。

上游语法和模板约束参考：`vendor/afsim/afsim-skill/SKILL.md`。本项目适配将其文件写入与验证步骤交给现有受控编译/运行服务，模型不直接执行shell或写权威状态。
